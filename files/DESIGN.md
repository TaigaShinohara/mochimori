# バッテリー節電アプリ 設計案 v0.3（2026-11-18、UX審査を反映。審査記録は files/UX_REVIEW_v0.1.0.md）

v0.3 の追加原則: 画面の文言は「実際に起きること」だけを書く。実装が追いつくまで約束を小さくする（正直さの強化）。v0.2.0 実装範囲は UX_REVIEW の §v0.3反映 1〜9 を正とする。

仮称: もち守り
対象: まず本人の Pixel 10 Pro（Android 15/16想定）。最終ゴールはストアリリース。

## 1. コンセプト（meaningful_app_design の3点）

- 何を一番体験させたいか: 「何もしなくても、電池が持つ」
- どう思ってほしいか: 「見守られてる。でも、うるさくない」
- 実現方法: 設定項目を並べない。残量・温度・使い方を見て、アプリ側が先回りで自動調整＋必要な時だけ1タップ提案。ホーム画面の主役は1つだけ＝「あと何時間持つか」。

やらないこと: グラフと数字で脅す／設定トグルを大量に並べる／できないことをできるように見せる。

アート方針（案）: 静かな見守り。深いネイビー＋柔らかい青白、Simple Glass の読み物ガラスを土台に。状態色は役割固定（正常=淡青、注意=オレンジ、緊急=ピンク）。アニメーションは状態が変わった時だけ。

## 2. Android の正直な線引き

### A. 許可なし〜軽い許可で「完全自動」でできる
- 電池残量・温度・電圧・充電状態の監視と「あと何時間」予測
- 充電 80% / 100% 到達通知、過充電・発熱（例: 40℃超）の気づき通知
- 自アプリ内のダークテーマ切替、画面表示の最適化
- アプリ別 電池使用量の見える化（要 PACKAGE_USAGE_STATS = 使用状況アクセス、ユーザーが1回許可）
- Wi-Fi / Bluetooth / 位置情報 / 5G / 明るさ高すぎ 等の「無駄の検知」と提案カード表示

### B. WRITE_SETTINGS（システム設定の変更）を1回許可すれば自動でできる
- 画面の明るさの自動調整（例: 残量30%以下で段階的に下げる、夜間は下げる）
- 画面消灯時間の自動短縮（例: 通常30秒 → 節電時15秒）
- 着信音・バイブ等の軽いプロファイル切替（範囲は要検証）
- ※許可は通常のポップアップではなく設定画面へ誘導する方式。Play審査は通る範囲だが、用途説明とプライバシーポリシーが必須。

### C. OSが自動を禁止 — 「1タップアシスト」が限界（自動っぽく見せない）
- 省電力モード ON: 直接切替不可（WRITE_SECURE_SETTINGS が必要で一般配布では使わない）→ 設定画面を直接開くボタンまで用意
- Wi-Fi / Bluetooth の OFF: Android 10以降、一般アプリは無断で切れない → 検知して提案＋パネル/設定へ1タップ遷移
- 他アプリのバックグラウンド制限: そのアプリの電池設定画面へ1タップ遷移まで
- データセーバー / 機内モード等も同類

### D. できない（明示する）
- 他アプリの強制停止・完全なキル（KILL_BACKGROUND_PROCESSES は実効性なし、強制停止は不可）
- CPU/GPU クロック制限、システムの省電力モード無断ON
- Wi-Fi の無断OFF、他アプリの通信遮断
- これらを謳う既存の節電アプリ的表現はしない。誇大表示は審査・信頼両面でマイナス。

### 使わないと決める権限
- WRITE_SECURE_SETTINGS: 使わない（要PC/ADB付与、ストア配布と両立しない）
- アクセシビリティサービス: 使わない（自動操作の代用にすると Play の用途外使用で審査高リスク。本来は支援用途）
- デバイス管理者 / Device Owner: 使わない（一般ユーザー配布に不適）

使う権限の審査影響まとめ:
- WRITE_SETTINGS: 低〜中。用用途を初回に1画面で説明。
- PACKAGE_USAGE_STATS: 中。使用量データの扱いをポリシー明記、外部送信なしを原則に。
- POST_NOTIFICATIONS / FOREGROUND_SERVICE (specialUse): 中。Android 14以降は用途宣言が必要。常駐は最小化し、WorkManager併用を検討。

## 3. 自動プロファイル（核の仕組み）

- 通常（31%〜）: 何もしない。見守るだけ。
- 節電（30%以下で自動）: 明るさ↓、消灯15秒、自アプリダーク、提案カードを出す。
- 緊急（15%以下で自動）: 明るさ最低寄り＋「省電力モードをONに」1タップボタンを大きく出す、充電スポット提案は将来枠。
- 充電中: プロファイル解除、80%で「抜くと長持ち」通知（ON/OFF可）。
- ルールは初期値で決めて選択肢を消す。変えたい人だけ詳細設定へ（minimal_information_design 原則5）。

Pixel の Adaptive Battery / Adaptive Charging との差別化: OS機能の代替ではなく、その上に乗る「横断の自動運転＋習慣の見える化」。OS設定がOFFなら検知して案内する側に回る。

## 4. 画面（2つだけ。v0.3.14 で気づきを廃止し3つから2つに。経緯は §11）

1. ホーム: 主役=画面中央の大きなバッテリー・イラスト（下記 §4.1）。数字は補助に降格。やることがある時だけ1タップボタン。下部に主アクション。**（v0.3.3 で仕様変更: 「あと何時間」の目安はイラストの下の常時表示をやめ、「数値を見る」の折りたたみ内へ移設した。経緯は §8 と docs/INFO_MIN_REVIEW_v0.3.2.md の R-7。）**

### 4.1 状態表現 — 中央バッテリーがすべてを語る（本人指示 2026-11-18）

- 判定は2値で言い切る: 「節電できてる」／「節電できてない」。中間の曖昧な表現でごまかさない。判定材料: 自動プロファイルが働いているか、無駄（明るさ過大・Wi-Fi/BT放置・発熱・電池食いアプリ等）が検知されているか。
- 節電できてない時: 燃えさかるバッテリー。炎が揺れるアニメーション、オレンジ基調、熱を感じる見た目。ただし脅しにはしない — 下に「理由1つ＋直し方1タップ」だけ添える。
- 節電できてる時: 静かでひんやりしたバッテリー。淡青基調、雪の結晶／冷気のゆらぎ、動きは最小限でゆっくり。安心感が主役。
- 文字は状態ラベル1語＋理由1行まで（minimal_information_design）。色だけに頼らず、炎／結晶の形でも区別する（アクセシビリティ）。
- アニメーションは状態の意味そのものなので許可（meaningful の3問テスト合格）。OSの「動きを減らす」設定では静止画に切替。
2. ルール: 自動プロファイルの確認と微調整だけ。トグル大量列挙はしない。

（旧・気づき画面は v0.3.14 で廃止した。当初は週1回「今週の無駄」最大3件の想定だったが、週集計が未実装のまま「今の無駄」の暫定表示だけが残り、出すものがない画面になっていた。本人が選択肢から「気づきタブを無くして2タブにする」を選んで廃止が決まった。経緯と判断は §11。）

オンボーディング: 3ステップ（①何が自動か/何が1タップか正直に ②権限は2つだけ順に ③終わり）。「あとで試す」は完了扱い。

### 4.2 気づき画面（詳細確定 2026-11-18、v0.3.14 で廃止 — 本節は廃止時点の記録）
- 主役: 「今週の無駄」最大3件だけ。毎日は出さない、週1回だけ。
- 各件は バーで量を示す＋理由1行＋「直す」1タップ。例: 明るさ最大のまま 2.1時間／特定アプリの裏での電池食い／100%充電のまま放置。
- 3件を超える分は捨てる（minimal 原則5）。責める文言は使わない。

### 4.3 ルール画面（詳細確定 2026-11-18）
- 主役: 自動プロファイルの状態（通常／節電／緊急の階段図）。
- 設定は4つまで: 自動節電 ON/OFF、節電に入る残量（初期値30%）、80%通知 ON/OFF、発熱通知 ON/OFF。
- それ以外は既定値に埋める。トグル列挙はしない。
- （v0.3.3: 節電に入る残量は固定値のまま、表示は独立した行を持たず階段図の「節電 30%以下」に一本化した。監査 R-2。）

### 4.4 画面遷移
ホーム ⇄ ルール は下部2タブ（v0.3.14 で気づきを廃止するまでは下部3タブだった）。ホームが常に起点。状態が燃えてる時はホームの1タップボタンから直接その理由の修正へ飛ぶ。

## 5. MVP（v1.0 の範囲）

入れる: A＋B＋C のうち 明るさ/消灯/80%通知/発熱通知/使用量見える化/省電力1タップ。
入れない: 他アプリ制御のふり、アクセシビリティ自動化、複雑なAI予測（予測は単純な直近消費ベースから）。

未確認: Pixel 10 Pro 実機での WRITE_SETTINGS 挙動、Foreground Service の電池消費自体（アプリ自身が電池を食う矛盾の測定）、Play の FOREGROUND_SERVICE specialUse 宣言文面。

## 7. v0.4 デザイン方式 — Material Design 3 化（v0.3.0、2026-11-19、本人指示）

- デザインの実装方式として Material Design 3（M3）を採用した。世界の言葉・状態色の役割固定（本書と ART_DIRECTION）は維持し、M3 はその実装方式とする。
- テーマ: Material Components for Android 1.12.0 の Theme.Material3.DayNight を土台に、ネイビー＋青白から作った M3 カラースキーム（light/dark）をセマンティックロールで定義。Android 12+ では Dynamic Colors を標準ロールに適用し、顔の状態色だけはカスタム属性の固定ロールで上書きされないようにした（線引きは ART_DIRECTION「Dynamic Color の位置づけ」）。
- 状態色の対応: ひんやり=primary 系＋固定状態ロール、注意=カスタム warning ロール（M3 標準に無いため追加し文書化）、緊急=error 系、補助構造=tertiary 系。色だけに頼らない原則（炎／結晶の形）は維持。
- コンポーネント: 自作タブバーを Navigation Bar に置換、Top App Bar 追加、主アクションは Filled Button／副次は Text Button、気づき項目とルール階段は Material Card、スイッチは MaterialSwitch、進み具合は Linear Progress Indicator。採用一覧は docs/UI_CATALOG.md。
- タイポグラフィは M3 タイプスケール、シェイプはトークン（4/8/12/20/28dp、ピルはボタンとナビインジケータだけ）。ダークテーマは DayNight でシステム追従（v0.2.0 の Light 固定を解消）、システムバーは edge-to-edge で処理。
- 機能は v0.2.0 から変更なし（デザイン改修のみ）。実機での見え方・ダークモード・Dynamic Color の実際の色は未確認。

## 6. v0.2.0 実装メモ（2026-11-19）

- 自動チェックと通知は AlarmManager（inexact repeating、約15分間隔）＋ BroadcastReceiver で実装。Foreground Service も WorkManager も使わない（依存ゼロ・最も軽い方式のため）。
- 正直な限界: チェックは約15分ごとで、OS のバッチング／Doze により通知・自動適用は最大で15分以上遅れることがある。即時ではない。再起動後はアプリを開くまで定期チェックは止まる（BOOT 権限を足さない方針のため）。
- 80%通知は充電セッションごとに1回、発熱通知は1時間に1回まで。
- 自動プロファイル適用時は元の明るさ・明るさモード・消灯時間を保存し、通常域に戻ったら復元する。「作動中」表示は実際に適用済みの時だけ出す。

情報最小化監査（docs/INFO_MIN_REVIEW_v0.3.2.md）の必須2件＋推奨10件をすべて適用した。詳細と削減前後の数値は監査記録 §10 が正本。

- HEAT 時の説明文は本文コントラスト確保のため onSurface で表示し、warning 色は見出し・バーだけに使う。
- 気づきのサンプルカードは撤去（週集計の実装時に実データとして復帰）。良好セクションは既定で畳む。
- ルールの「約15分ごと」注記は常設をやめ、自動節電を ON にした時にトーストで1回だけ伝える後出しにした。

## 9. ホーム画面ウィジェット（v0.3.12、2026-11-20、本人指示「ウィジェットで置けるようにしておいて」）

- 形態: AppWidgetProvider（MochiWidgetProvider）。最小サイズ 2×2 セル（110dp 四方）、横・縦リサイズ可。タップでアプリ本体（ホーム画面）が開く。ウィジェット上の操作ボタンは置かない。
- 表示: 顔の静止画＋状態ラベル1語＋残量％のみ（ホーム画面の最小形。理由文は載せない）。状態ラベルと色はホームと同一（節電できてる／充電中=stateCool、節電できてない=warning、残量わずか=error、確認中=onSurfaceVariant）。
- 顔の描画: ウィジェットではカスタムViewのアニメーションが使えないため、WidgetFaceRenderer が Canvas で Bitmap に描いた静止画を ImageView に載せる。BatteryFaceView の寸法言語（縦型 1：1.55、上部中央キャップ、液体は残量分だけ下から満ちる）と固定状態色を簡略化して再現する。液面は静かな波で凍結、炎は直立した静止画、結晶は同配置、稲妻は充電中のみ。液体アニメーション・傾き連動・パーティクル・触覚フィードバックはウィジェットでは行わない（静止画であることを盛らない）。
- 判定: BatteryJudge をそのまま再利用（MainActivity と同じ Input の組み立て）。ウィジェット用に判定を二重実装しない。
- パネル: Simple Glass の言語に寄せた角丸パネル（半透明面＋ふちハイライト、ライト／ダーク両対応で端末テーマに追従）。壁紙の上に浮く面のため厚みは帯と同じ重ね面級。
- 更新タイミング（正直な限界）: ①システムのウィジェット更新スケジュール 30分（updatePeriodMillis=1800000 はプラットフォームの下限で、これより短くできない）②アプリの定期チェック（約15分）が走った時に AppWidgetManager 経由で連動更新。それ以外の即時更新（充電開始・抜き差し等）は実装しない — 表示が実際の状態から最大で数十分遅れることがある。
- 権限: 追加なし（WRITE_SETTINGS／POST_NOTIFICATIONS／VIBRATE の3つのまま）。再起動後の即時復帰に要る RECEIVE_BOOT_COMPLETED も足さない（30分スケジュールは再起動後もシステムが保持し、定期チェックは従来どおりアプリを開くまで止まる）。
- 未確認: ウィジェットの実際の見え方・配置・ランチャーごとのリサイズ挙動は実機のホーム画面でしか判定できない（実機待ち行列）。

## 10. 残り時間と電池の健康（v0.3.13、2026-11-20、本人要望「劣化状態やあとどれくらい使えるかも見れるように。あとどれくらいでバッテリー0になるかも」）

表示場所はホームの「数値を見る」折りたたみ内のみ（詳細情報として）。ホームの常時表示は増やさない（情報最小化の既存方針）。気づき画面には追加しない。

### 10.1 あとどれくらい使えるか（0%までの推定時間）
- 放電中: 実測の履歴から消費ペース（%/時）を出し、「あと約X時間Y分で0%（目安）」と表示する。計算は純粋関数 BatteryPace.estimateMinutesToEmpty:
  - 対象は「最後の充電以降の放電セッション」のみ。前の充電サイクルの減り方は混ぜない。
  - ペースに使うのは直近6時間の窓の最古→最新の実測ドロップ。観測スパン30分未満、またはドロップ2%未満（整数%の量子化ノイズ域）の場合は推定を出さず「0%までの時間は計測中」と表示する。数字をでっち上げない。
- 充電中: BatteryManager.computeChargeTimeRemaining()（API 28+）が正の値を返した場合だけ「満充電まで約X時間Y分（目安）」を表示する。返らない場合は無理に出さない。80%通知の文脈は従来どおり不変。
- 旧仕様の置き換え: v0.3.3（監査 R-7）で折りたたみ内に入れた「目安 約X時間」（残量×18時間の粗い比例）は本節の実測ベースに置き換えて廃止した。BatteryJudge からも estimatedHours を撤去した（推定が2系統あると矛盾した数字が並ぶため）。

### 10.2 履歴の保持仕様
- 記録タイミング: 定期チェック（BatteryCheckReceiver、約15分間隔）のたび＋アプリがスナップショットを読んだ時（ホーム表示時）。どちらも BatteryHistory.record が「直近サンプルと同値・同充電状態で5分未満」の記録は捨てるため、開閉の繰り返しで膨らまない。
- 記録内容: （時刻ms、残量%、充電中か）の3値のみ。SharedPreferences（battery_history / samples_v1）に "時刻:残量:充電01" のカンマ列で軽量に保持。
- 保持範囲: 最大64件、かつ48時間以内。古いものは prune で捨てる。再起動後も残る（SharedPreferences のため）。BOOT 権限は足さない方針は維持 — 再起動後は従来どおりアプリを開くまで記録は止まり、開いた時点から再開する。

### 10.3 バッテリーの健康状態
情報源は ACTION_BATTERY_CHANGED の sticky broadcast と BatteryManager プロパティ。一般アプリから設計容量は取得できないため、**劣化％のような断定表示はしない**。端末が返したものだけを出し、取れない項目は行ごと出さない（「不明」を並べない）:
- ヘルス状態: EXTRA_HEALTH の人間語化（良好／過熱しています／異常／電圧が高すぎます／冷えすぎています）。BATTERY_HEALTH_UNKNOWN と未取得は行を出さない。
- サイクル数: EXTRA_CYCLE_COUNT（API 34+、端末が値を入れた場合のみ）。「サイクル数 約N回」。取れない端末・OS では行を出さない。
- 満充電容量の推定: BATTERY_PROPERTY_CHARGE_COUNTER（µAh）と残量%からの外挿。「満充電容量 約X,XXXmAh（推定）」と必ず推定表記にする。残量20%未満（整数%の丸めが増幅される域）・カウンタ未対応・結果が 500〜30,000mAh の妥当域外の場合は出さない。
- 電圧: EXTRA_VOLTAGE を既存の数値行（残量・温度・明るさ）に統合して追加（「電圧 4.02V」、未取得時は付けない）。

### 10.4 制約と未確認
- 権限: 追加なし（WRITE_SETTINGS／POST_NOTIFICATIONS／VIBRATE の3つのまま）。

## 12. 節電チェックリスト（v0.3.15、2026-11-20、本人要望「節電できてるかどうかはチェックリストで見れるようにして。できてない項目を押したら設定画面に飛ぶか、やり方を説明するようにして」）

ホーム画面に「節電チェック」のカード（読み物ガラス）を追加した。配置は「数値を見る」チップと詳細、その下で、緊急時の大きなボタンより下（緊急ボタンの優先度は下げない）。判定は純粋関数 SavingChecklist が担い、顔の判定（BatteryJudge）と矛盾しないよう基準を共有する。

### 12.1 項目と基準（すべて実測値から判定）
1. **画面の明るさ**: 自動調整モードなら「できてる（自動）」。手動時は BatteryJudge と同じ閾値 230/255 以上で「できてない」。値は「N/255」。
2. **画面が消えるまでの時間**: SCREEN_OFF_TIMEOUT を読み、30秒以下で「できてる」。「消えない設定」（Int.MAX_VALUE）は「できてない」。
3. **バッテリーの温度**: BatteryJudge と同じ発熱閾値 40℃ 以上で「できてない」。
4. **省電力モード**: PowerManager.isPowerSaveMode。ON なら「できてる」。OFF でも残量が自動プロファイルの階段閾値（30%）より多ければ中立（「OFF（今は大丈夫）」で「できてる」扱い）とし、30%以下で OFF の時だけ「できてない」。充電中は OS が OFF にするのが正常なので「できてる（充電中）」。残量が読めない時は判定しない。
5. **自動節電（このアプリのルール）**: ルール画面の自動節電トグルの状態。OFF は「できてない」。ON でも WRITE_SETTINGS 許可が無い時はプロファイルが実際には動かせないため「確認中（許可が必要）」とする（BatteryJudge の NEED_PERMISSION と同じ線引き）。

### 12.2 取れない値の扱い
値が取得できない項目は「確認中」（？マーク）とし、できてる風には見せない。カード頭の要約は「5つ中4つ できてる」形式で、確認中がある時は「4つ中4つ できてる（1つ確認中）」と分母から除いて正直に数える。全項目できてる時は「5つとも できてる」。

### 12.3 タップ動作
- 明るさ／消灯時間 → 画面設定（ACTION_DISPLAY_SETTINGS、失敗時は設定トップへフォールバック）
- 温度 → 冷まし方の説明ダイアログ（設定画面が存在しないため。「重いアプリを閉じる／充電しながらの使用を控える／ケースを外して涼しい場所で休ませる」）
- 省電力モード → 省電力設定（ACTION_BATTERY_SAVER_SETTINGS、既存の openBatterySaverSettings と同じ経路）
- 自動節電 → ルール画面へアプリ内遷移。ただし「許可が必要」の状態の時は既存の許可導線（ACTION_MANAGE_WRITE_SETTINGS）へつなぐ

### 12.4 表示の作法
- 状態マークは形＋色の両方で区別する: できてる=淡青（cool ロール）の丸に ✓、できてない=オレンジ（warning ロール）の丸に ！、確認中= surfaceVariant の丸に ？。値の文字色は全状態で onSurfaceVariant に統一し、本文に warning 色を使わない原則（監査 M-1）を守る。
- 各行は「マーク＋項目名＋今の値」の1行、タップ領域 48dp、行の読み上げは「項目名＋値」。
- 権限: 追加なし（WRITE_SETTINGS／POST_NOTIFICATIONS／VIBRATE の3つのまま）。設定値の読み取りは許可不要の範囲で成立する。
- 未確認: 設定画面が実際に開くか、ダイアログと行の実機での見え方は実機でしか判定できない（実機待ち行列）。
