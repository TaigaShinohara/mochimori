# バッテリー節電アプリ 設計案 v0.3（2026-11-18、UX審査を反映。審査記録は files/UX_REVIEW_v0.1.0.md）

v0.3 の追加原則: 画面の文言は「実際に起きること」だけを書く。実装が追いつくまで約束を小さくする（正直さの強化）。v0.2.0 実装範囲は UX_REVIEW の §v0.3反映 1〜9 を正とする。

仮称: もち守り
対象: まず本人の Pixel 10 Pro（Android 15/16想定）。最終ゴールはストアリリース。

## 1. コンセプト（meaningful_app_design の3点）

- 何を一番体験させたいか: 「何もしなくても、電池が持つ」
- どう思ってほしいか: 「見守られてる。でも、うるさくない」
- 実現方法: 設定項目を並べない。残量・温度・使い方を見て、アプリ側が先回りで自動調整＋必要な時だけ1タップ提案。ホーム画面の主役は1つだけ＝「あと何時間持つか」。

やらないこと: グラフと数字で脅す／設定トグルを大量に並べる／できないことをできるように見せる。

アート方針（案）: 静かな見守り。深いネイビー＋柔らかい青白、Simple Glass の読み物ガラスを土台に。状態色は役割固定（正常=淡青、注意=オレンジ、緊急=ピンク）。アニメーションは状態が変わった時だけ。

## 2. Android の正直な線引き

### A. 許可なし〜軽い許可で「完全自動」でできる
- 電池残量・温度・電圧・充電状態の監視と「あと何時間」予測
- 充電 80% / 100% 到達通知、過充電・発熱（例: 40℃超）の気づき通知
- 自アプリ内のダークテーマ切替、画面表示の最適化
- アプリ別 電池使用量の見える化（要 PACKAGE_USAGE_STATS = 使用状況アクセス、ユーザーが1回許可）
- Wi-Fi / Bluetooth / 位置情報 / 5G / 明るさ高すぎ 等の「無駄の検知」と提案カード表示

### B. WRITE_SETTINGS（システム設定の変更）を1回許可すれば自動でできる
- 画面の明るさの自動調整（例: 残量30%以下で段階的に下げる、夜間は下げる）
- 画面消灯時間の自動短縮（例: 通常30秒 → 節電時15秒）
- 着信音・バイブ等の軽いプロファイル切替（範囲は要検証）
- ※許可は通常のポップアップではなく設定画面へ誘導する方式。Play審査は通る範囲だが、用途説明とプライバシーポリシーが必須。

### C. OSが自動を禁止 — 「1タップアシスト」が限界（自動っぽく見せない）
- 省電力モード ON: 直接切替不可（WRITE_SECURE_SETTINGS が必要で一般配布では使わない）→ 設定画面を直接開くボタンまで用意
- Wi-Fi / Bluetooth の OFF: Android 10以降、一般アプリは無断で切れない → 検知して提案＋パネル/設定へ1タップ遷移
- 他アプリのバックグラウンド制限: そのアプリの電池設定画面へ1タップ遷移まで
- データセーバー / 機内モード等も同類

### D. できない（明示する）
- 他アプリの強制停止・完全なキル（KILL_BACKGROUND_PROCESSES は実効性なし、強制停止は不可）
- CPU/GPU クロック制限、システムの省電力モード無断ON
- Wi-Fi の無断OFF、他アプリの通信遮断
- これらを謳う既存の節電アプリ的表現はしない。誇大表示は審査・信頼両面でマイナス。

### 使わないと決める権限
- WRITE_SECURE_SETTINGS: 使わない（要PC/ADB付与、ストア配布と両立しない）
- アクセシビリティサービス: 使わない（自動操作の代用にすると Play の用途外使用で審査高リスク。本来は支援用途）
- デバイス管理者 / Device Owner: 使わない（一般ユーザー配布に不適）

使う権限の審査影響まとめ:
- WRITE_SETTINGS: 低〜中。用用途を初回に1画面で説明。
- PACKAGE_USAGE_STATS: 中。使用量データの扱いをポリシー明記、外部送信なしを原則に。
- POST_NOTIFICATIONS / FOREGROUND_SERVICE (specialUse): 中。Android 14以降は用途宣言が必要。常駐は最小化し、WorkManager併用を検討。

## 3. 自動プロファイル（核の仕組み）

- 通常（31%〜）: 何もしない。見守るだけ。
- 節電（30%以下で自動）: 明るさ↓、消灯15秒、自アプリダーク、提案カードを出す。
- 緊急（15%以下で自動）: 明るさ最低寄り＋「省電力モードをONに」1タップボタンを大きく出す、充電スポット提案は将来枠。
- 充電中: プロファイル解除、80%で「抜くと長持ち」通知（ON/OFF可）。
- ルールは初期値で決めて選択肢を消す。変えたい人だけ詳細設定へ（minimal_information_design 原則5）。

Pixel の Adaptive Battery / Adaptive Charging との差別化: OS機能の代替ではなく、その上に乗る「横断の自動運転＋習慣の見える化」。OS設定がOFFなら検知して案内する側に回る。

## 4. 画面（2つだけ。v0.3.14 で気づきを廃止し3つから2つに。経緯は §11）

1. ホーム: 主役=画面中央の大きなバッテリー・イラスト（下記 §4.1）。数字は補助に降格。やることがある時だけ1タップボタン。下部に主アクション。**（v0.3.3 で仕様変更: 「あと何時間」の目安はイラストの下の常時表示をやめ、「数値を見る」の折りたたみ内へ移設した。経緯は §8 と docs/INFO_MIN_REVIEW_v0.3.2.md の R-7。）**

### 4.1 状態表現 — 中央バッテリーがすべてを語る（本人指示 2026-11-18）

- 判定は2値で言い切る: 「節電できてる」／「節電できてない」。中間の曖昧な表現でごまかさない。判定材料: 自動プロファイルが働いているか、無駄（明るさ過大・Wi-Fi/BT放置・発熱・電池食いアプリ等）が検知されているか。
- 節電できてない時: 燃えさかるバッテリー。炎が揺れるアニメーション、オレンジ基調、熱を感じる見た目。ただし脅しにはしない — 下に「理由1つ＋直し方1タップ」だけ添える。
- 節電できてる時: 静かでひんやりしたバッテリー。淡青基調、雪の結晶／冷気のゆらぎ、動きは最小限でゆっくり。安心感が主役。
- 文字は状態ラベル1語＋理由1行まで（minimal_information_design）。色だけに頼らず、炎／結晶の形でも区別する（アクセシビリティ）。
- アニメーションは状態の意味そのものなので許可（meaningful の3問テスト合格）。OSの「動きを減らす」設定では静止画に切替。
2. ルール: 自動プロファイルの確認と微調整だけ。トグル大量列挙はしない。

（旧・気づき画面は v0.3.14 で廃止した。当初は週1回「今週の無駄」最大3件の想定だったが、週集計が未実装のまま「今の無駄」の暫定表示だけが残り、出すものがない画面になっていた。本人が選択肢から「気づきタブを無くして2タブにする」を選んで廃止が決まった。経緯と判断は §11。）

オンボーディング: 3ステップ（①何が自動か/何が1タップか正直に ②権限は2つだけ順に ③終わり）。「あとで試す」は完了扱い。

### 4.2 気づき画面（詳細確定 2026-11-18、v0.3.14 で廃止 — 本節は廃止時点の記録）
- 主役: 「今週の無駄」最大3件だけ。毎日は出さない、週1回だけ。
- 各件は バーで量を示す＋理由1行＋「直す」1タップ。例: 明るさ最大のまま 2.1時間／特定アプリの裏での電池食い／100%充電のまま放置。
- 3件を超える分は捨てる（minimal 原則5）。責める文言は使わない。

### 4.3 ルール画面（詳細確定 2026-11-18）
- 主役: 自動プロファイルの状態（通常／節電／緊急の階段図）。
- 設定は4つまで: 自動節電 ON/OFF、節電に入る残量（初期値30%）、80%通知 ON/OFF、発熱通知 ON/OFF。
- それ以外は既定値に埋める。トグル列挙はしない。
- （v0.3.3: 節電に入る残量は固定値のまま、表示は独立した行を持たず階段図の「節電 30%以下」に一本化した。監査 R-2。）

### 4.4 画面遷移
ホーム ⇄ ルール は下部2タブ（v0.3.14 で気づきを廃止するまでは下部3タブだった）。ホームが常に起点。状態が燃えてる時はホームの1タップボタンから直接その理由の修正へ飛ぶ。

## 5. MVP（v1.0 の範囲）

入れる: A＋B＋C のうち 明るさ/消灯/80%通知/発熱通知/使用量見える化/省電力1タップ。
入れない: 他アプリ制御のふり、アクセシビリティ自動化、複雑なAI予測（予測は単純な直近消費ベースから）。

未確認: Pixel 10 Pro 実機での WRITE_SETTINGS 挙動、Foreground Service の電池消費自体（アプリ自身が電池を食う矛盾の測定）、Play の FOREGROUND_SERVICE specialUse 宣言文面。

## 7. v0.4 デザイン方式 — Material Design 3 化（v0.3.0、2026-11-19、本人指示）

- デザインの実装方式として Material Design 3（M3）を採用した。世界の言葉・状態色の役割固定（本書と ART_DIRECTION）は維持し、M3 はその実装方式とする。
- テーマ: Material Components for Android 1.12.0 の Theme.Material3.DayNight を土台に、ネイビー＋青白から作った M3 カラースキーム（light/dark）をセマンティックロールで定義。Android 12+ では Dynamic Colors を標準ロールに適用し、顔の状態色だけはカスタム属性の固定ロールで上書きされないようにした（線引きは ART_DIRECTION「Dynamic Color の位置づけ」）。
- 状態色の対応: ひんやり=primary 系＋固定状態ロール、注意=カスタム warning ロール（M3 標準に無いため追加し文書化）、緊急=error 系、補助構造=tertiary 系。色だけに頼らない原則（炎／結晶の形）は維持。
- コンポーネント: 自作タブバーを Navigation Bar に置換、Top App Bar 追加、主アクションは Filled Button／副次は Text Button、気づき項目とルール階段は Material Card、スイッチは MaterialSwitch、進み具合は Linear Progress Indicator。採用一覧は docs/UI_CATALOG.md。
- タイポグラフィは M3 タイプスケール、シェイプはトークン（4/8/12/20/28dp、ピルはボタンとナビインジケータだけ）。ダークテーマは DayNight でシステム追従（v0.2.0 の Light 固定を解消）、システムバーは edge-to-edge で処理。
- 機能は v0.2.0 から変更なし（デザイン改修のみ）。実機での見え方・ダークモード・Dynamic Color の実際の色は未確認。

## 6. v0.2.0 実装メモ（2026-11-19）

- 自動チェックと通知は AlarmManager（inexact repeating、約15分間隔）＋ BroadcastReceiver で実装。Foreground Service も WorkManager も使わない（依存ゼロ・最も軽い方式のため）。
- 正直な限界: チェックは約15分ごとで、OS のバッチング／Doze により通知・自動適用は最大で15分以上遅れることがある。即時ではない。再起動後はアプリを開くまで定期チェックは止まる（BOOT 権限を足さない方針のため）。
- 80%通知は充電セッションごとに1回、発熱通知は1時間に1回まで。
- 自動プロファイル適用時は元の明るさ・明るさモード・消灯時間を保存し、通常域に戻ったら復元する。「作動中」表示は実際に適用済みの時だけ出す。

情報最小化監査（docs/INFO_MIN_REVIEW_v0.3.2.md）の必須2件＋推奨10件をすべて適用した。詳細と削減前後の数値は監査記録 §10 が正本。

- 気づきのサンプルカードは撤去（週集計の実装時に実データとして復帰）。良好セクションは既定で畳む。

## 9. ホーム画面ウィジェット（v0.3.12、2026-11-20、本人指示「ウィジェットで置けるようにしておいて」）

- 形態: AppWidgetProvider（MochiWidgetProvider）。最小サイズ 2×2 セル（110dp 四方）、横・縦リサイズ可。タップでアプリ本体（ホーム画面）が開く。ウィジェット上の操作ボタンは置かない。
- 表示: 顔の静止画＋状態ラベル1語＋残量％のみ（ホーム画面の最小形。理由文は載せない）。状態ラベルと色はホームと同一（節電できてる／充電中=stateCool、節電できてない=warning、残量わずか=error、確認中=onSurfaceVariant）。
- 顔の描画: ウィジェットではカスタムViewのアニメーションが使えないため、WidgetFaceRenderer が Canvas で Bitmap に描いた静止画を ImageView に載せる。BatteryFaceView の寸法言語（縦型 1：1.55、上部中央キャップ、液体は残量分だけ下から満ちる）と固定状態色を簡略化して再現する。液面は静かな波で凍結、炎は直立した静止画、結晶は同配置、稲妻は充電中のみ。液体アニメーション・傾き連動・パーティクル・触覚フィードバックはウィジェットでは行わない（静止画であることを盛らない）。
- 判定: BatteryJudge をそのまま再利用（MainActivity と同じ Input の組み立て）。ウィジェット用に判定を二重実装しない。
- パネル: Simple Glass の言語に寄せた角丸パネル（半透明面＋ふちハイライト、ライト／ダーク両対応で端末テーマに追従）。壁紙の上に浮く面のため厚みは帯と同じ重ね面級。
- 更新タイミング（正直な限界）: ①システムのウィジェット更新スケジュール 30分（updatePeriodMillis=1800000 はプラットフォームの下限で、これより短くできない）②アプリの定期チェック（約15分）が走った時に AppWidgetManager 経由で連動更新。それ以外の即時更新（充電開始・抜き差し等）は実装しない — 表示が実際の状態から最大で数十分遅れることがある。
- 権限: 追加なし（WRITE_SETTINGS／POST_NOTIFICATIONS／VIBRATE の3つのまま）。再起動後の即時復帰に要る RECEIVE_BOOT_COMPLETED も足さない（30分スケジュールは再起動後もシステムが保持し、定期チェックは従来どおりアプリを開くまで止まる）。
- 未確認: ウィジェットの実際の見え方・配置・ランチャーごとのリサイズ挙動は実機のホーム画面でしか判定できない（実機待ち行列）。

## 10. 残り時間と電池の健康（v0.3.13、2026-11-20、本人要望「劣化状態やあとどれくらい使えるかも見れるように。あとどれくらいでバッテリー0になるかも」）

表示場所はホームの「数値を見る」折りたたみ内のみ（詳細情報として）。ホームの常時表示は増やさない（情報最小化の既存方針）。気づき画面には追加しない。

### 10.1 あとどれくらい使えるか（0%までの推定時間）
- 放電中: 実測の履歴から消費ペース（%/時）を出し、「あと約X時間Y分で0%」と表示する（目安表記は「約」に一本化。v0.3.24 — §18）。計算は純粋関数 BatteryPace.estimateMinutesToEmpty:
  - 対象は「最後の充電以降の放電セッション」のみ。前の充電サイクルの減り方は混ぜない。
  - ペースに使うのは直近6時間の窓の最古→最新の実測ドロップ。観測スパン30分未満、またはドロップ2%未満（整数%の量子化ノイズ域）の場合は推定を出さず「0%までの時間は計測中」と表示する。数字をでっち上げない。
- 充電中: BatteryManager.computeChargeTimeRemaining()（API 28+）が正の値を返した場合だけ「満充電まで約X時間Y分」を表示する。返らない場合は無理に出さない。80%通知の文脈は従来どおり不変。（v0.3.24: 目安表記は「約」に一本化し、末尾の「（目安）」は付けない — §18。）
- 旧仕様の置き換え: v0.3.3（監査 R-7）で折りたたみ内に入れた「目安 約X時間」（残量×18時間の粗い比例）は本節の実測ベースに置き換えて廃止した。BatteryJudge からも estimatedHours を撤去した（推定が2系統あると矛盾した数字が並ぶため）。

### 10.2 履歴の保持仕様
- 記録タイミング: 定期チェック（BatteryCheckReceiver、約15分間隔）のたび＋アプリがスナップショットを読んだ時（ホーム表示時）。どちらも BatteryHistory.record が「直近サンプルと同値・同充電状態で5分未満」の記録は捨てるため、開閉の繰り返しで膨らまない。
- 記録内容: （時刻ms、残量%、充電中か）の3値のみ。SharedPreferences（battery_history / samples_v1）に "時刻:残量:充電01" のカンマ列で軽量に保持。
- 保持範囲: 最大64件、かつ48時間以内。古いものは prune で捨てる。再起動後も残る（SharedPreferences のため）。BOOT 権限は足さない方針は維持 — 再起動後は従来どおりアプリを開くまで記録は止まり、開いた時点から再開する。

### 10.3 バッテリーの健康状態
情報源は ACTION_BATTERY_CHANGED の sticky broadcast と BatteryManager プロパティ。一般アプリから設計容量は取得できないため、**劣化％のような断定表示はしない**。端末が返したものだけを出し、取れない項目は行ごと出さない（「不明」を並べない）:
- ヘルス状態: EXTRA_HEALTH の人間語化（良好／過熱しています／異常／電圧が高すぎます／冷えすぎています）。BATTERY_HEALTH_UNKNOWN と未取得は行を出さない。
- サイクル数: EXTRA_CYCLE_COUNT（API 34+、端末が値を入れた場合のみ）。「サイクル数 約N回」。取れない端末・OS では行を出さない。
- 満充電容量の推定: BATTERY_PROPERTY_CHARGE_COUNTER（µAh）と残量%からの外挿。「満充電容量 約X,XXXmAh（推定）」と必ず推定表記にする。残量20%未満（整数%の丸めが増幅される域）・カウンタ未対応・結果が 500〜30,000mAh の妥当域外の場合は出さない。
- 電圧: EXTRA_VOLTAGE を既存の数値行（残量・温度・明るさ）に統合して追加（「電圧 4.02V」、未取得時は付けない）。

### 10.4 制約と未確認
- 権限: 追加なし（WRITE_SETTINGS／POST_NOTIFICATIONS／VIBRATE の3つのまま）。

## 12. 節電チェックリスト（v0.3.15、2026-11-20、本人要望「節電できてるかどうかはチェックリストで見れるようにして。できてない項目を押したら設定画面に飛ぶか、やり方を説明するようにして」）

ホーム画面に「節電チェック」のカード（読み物ガラス）を追加した。配置は状態別アクションの下（緊急時の大きなボタンより下で、その優先度は下げない）。v0.3.15 の当初は「数値を見る」の下だったが、v0.3.18 の情報整理でチェックリストを「数値を見る」より上へ移した（経緯は §13）。判定は純粋関数 SavingChecklist が担い、顔の判定（BatteryJudge）と矛盾しないよう基準を共有する。

### 12.1 項目と基準（すべて実測値から判定）
1. **画面の明るさ**: 自動調整モードなら「できてる（自動）」。手動時は BatteryJudge と同じ閾値 230/255 以上で「できてない」。値は「N/255」。
2. **画面が消えるまでの時間**: SCREEN_OFF_TIMEOUT を読み、30秒以下で「できてる」。「消えない設定」（Int.MAX_VALUE）は「できてない」。
3. **バッテリーの温度**: BatteryJudge と同じ発熱閾値 40℃ 以上で「できてない」。
4. **省電力モード**: PowerManager.isPowerSaveMode。ON なら「できてる」。OFF でも残量が自動プロファイルの階段閾値（30%）より多ければ中立（「OFF（今は大丈夫）」で「できてる」扱い）とし、30%以下で OFF の時だけ「できてない」。充電中は OS が OFF にするのが正常なので「できてる（充電中）」。残量が読めない時は判定しない。
5. **自動節電（このアプリのルール）**: ルール画面の自動節電トグルの状態。OFF は「できてない」。ON でも WRITE_SETTINGS 許可が無い時はプロファイルが実際には動かせないため「確認中（許可が必要）」とする（BatteryJudge の NEED_PERMISSION と同じ線引き）。

### 12.2 取れない値の扱い
値が取得できない項目は「確認中」（？マーク）とし、できてる風には見せない。カード頭の要約は「5つ中4つ できてる」形式で、確認中がある時は「4つ中4つ できてる（1つ確認中）」と分母から除いて正直に数える。全項目できてる時は「5つとも できてる」。

### 12.3 タップ動作
（v0.3.25 で変更し v0.3.26 で拡張: 全項目のタップは直行せず、先に説明シートを出す。確定仕様は §12.7。以下はシートの主ボタンの先として現行。）
- 明るさ／消灯時間 → 画面設定（ACTION_DISPLAY_SETTINGS、失敗時は設定トップへフォールバック）。ただし「できてない」時は §12.7 のとおりアプリがその場で直す（シート経由）
- 温度 → 冷まし方の説明ダイアログ（設定画面が存在しないため。「重いアプリを閉じる／充電しながらの使用を控える／ケースを外して涼しい場所で休ませる」）
- 省電力モード → 省電力設定（ACTION_BATTERY_SAVER_SETTINGS、既存の openBatterySaverSettings と同じ経路）
- 自動節電 → ルール画面へアプリ内遷移。ただし「許可が必要」の状態の時は既存の許可導線（ACTION_MANAGE_WRITE_SETTINGS）へつなぐ

### 12.4 表示の作法
- 状態マークは形＋色の両方で区別する: できてる=淡青（cool ロール）の丸に ✓、できてない=オレンジ（warning ロール）の丸に ！、確認中= surfaceVariant の丸に ？。値の文字色は全状態で onSurfaceVariant に統一し、本文に warning 色を使わない原則（監査 M-1）を守る。
- 各行は「マーク＋項目名＋今の値」の1行、タップ領域 48dp、行の読み上げは「項目名＋値」。
- 権限: 追加なし（WRITE_SETTINGS／POST_NOTIFICATIONS／VIBRATE の3つのまま）。設定値の読み取りは許可不要の範囲で成立する。

### 12.5 v0.3.16 の拡充（2026-11-20、本人要望「チェックリストは増やそう。もっと節電するためのチェックを増やそう。可能な限り節電したい。そして、チェックリストはパーセントと円グラフで示そう」）

項目を増やし、カード頭の要約を「ドーナツ型の円グラフ＋大きな％数字」にした。追加した読み取りはすべて**新規権限なし**で成立するものだけ（権限は従来の3つのまま）。ConnectivityManager は使わない — その読み取りには ACCESS_NETWORK_STATE が要り、権限を増やさない約束に反するため。

追加項目と基準（すべて実読み）:
6. **Wi-Fi**: WifiManager.isWifiEnabled と WifiInfo の supplicant 状態で判定。OFF は「できてる」。ON で接続完了（SupplicantState.COMPLETED）は「できてる（接続中）」。ON で未接続が確定した時だけ「できてない」。supplicant 状態は WifiInfo の中で位置情報権限による秘匿（SSID／BSSID／networkId 等）の対象外なので、権限なしでも接続の有無が分かる。接続処理の途中（関連付け中・スキャン中など）は判定せず「確認中」。
7. **モバイルデータ**: グローバル設定キー "mobile_data" を直接読む（Settings.Global の定数は非公開APIのためキー文字列で読む）。ON は「できてない」、ただし Wi-Fi 接続中は通信が Wi-Fi 側に乗るため中立（「できてる（Wi-Fi接続中）」）。OFF は「できてる」。キーが読めない端末では項目自体を出さない（推測で並べない）。
8. **位置情報**: LocationManager.isLocationEnabled（API 28未満は Settings.Secure.LOCATION_MODE）。ON は「できてない」、OFF は「できてる」。読めない時は「確認中」。
9. **NFC**: NfcAdapter の状態。ON は「できてない」、OFF は「できてる」。NFC 非搭載の端末では項目自体を出さない。
10. **ダークテーマ（有機EL）**: 現在の実効ナイトモード（configuration の uiMode）で判定。ON は「できてる」、OFF は「できてない」。節電の前提は有機EL（暗い画素はほぼ電力を食わない）なので、前提は項目名に明記し、LCD では断定しない。
11. **タッチ時のバイブ**: Settings.System.HAPTIC_FEEDBACK_ENABLED。ON は「できてない」、OFF は「できてる」。設定キーが無い端末では「確認中」。

情報項目（％の分母に入れない）:
- **Bluetooth**: 接続中かどうかは BLUETOOTH_CONNECT なしでは判定できないため、ON/OFF だけでは断定しない。ON の時だけ案内行（i マーク＋「使っていなければ、OFFにすると節電になります」）を出し、％と要約の数には一切入れない。OFF・読めない時は行自体を出さない。

採用しなかった候補:
- **自動同期**: ContentResolver.getMasterSyncAutomatically() はシステムサーバー側で READ_SYNC_SETTINGS を強制される（公式ドキュメント・AOSP 実装で確認）。新規権限が要るため不採用。
- 常時表示（AOD）、リフレッシュレート、アダプティブバッテリーは、従来どおり読めない／効き目が誤解を招くため項目にしない。

％と円グラフ:
- ％ = できてる項目 ÷ 判定できる項目 × 100（四捨五入）。「確認中」と情報項目（Bluetooth）は分母から除く — §12.2 の正直な数え方をそのまま％に適用したもの。要約文（「○つ中○つ できてる」）は補助として頭に残す。
- 円グラフは専用 View（DonutChartView）が Canvas で描くドーナツ: トラックは surfaceVariant ロール、進みのアークは淡青（cool ロール）で真上から時計回り。中央に大きな％数字（TitleLarge・太字）。全項目できてる時は 100% ＋全周のアークで静かに示す。判定できる項目が1つも無い時は数字の代わりに「―」を出し、アークは描かない（数字をでっち上げない）。
- 円グラフの読み上げは「節電チェック ○パーセント、（要約文）」。

### 12.6 v0.3.17 の2段構成（2026-11-20、本人要望「通常の節電と、限界までやる節電でチェックリストを分けて。限界までやる方はそのモードにした時だけ出るようにして」）

チェックリストを「通常」と「限界」の2枚のカードに分けた。振り分けの物差しは**日常の快適さを捨てるかどうか**: 捨てずに済むものは通常、捨てる覚悟が要るものは限界。

**通常リスト（常時表示・7項目）**: 画面の明るさ／画面が消えるまでの時間／バッテリーの温度／省電力モード／自動節電（このアプリのルール）／Wi-Fi／ダークテーマ（有機EL）。基準は §12.1・§12.5 のまま変更なし。Wi-Fi は「接続中は○・未接続のままONだけ×」なので快適さを捨てず、ダークテーマも有機ELでは見た目の好みの範囲として通常に残した。

**限界リスト（モードONの時だけ表示）**: モバイルデータ／位置情報／NFC／Bluetooth／タッチ時のバイブ／データセーバー。いずれも OFF にすると日常の便利さが実際に落ちる（通信・決済・探し物・時計連携など）ため、本人が「限界までやる」と選んだ時だけ俎上に載せる。
- **Bluetooth は限界側では通常項目として数える**: 通常側では「接続中かどうかが BLUETOOTH_CONNECT なしでは読めない」ため案内行（分母外）だったが、限界モードの前提は「便利さを捨ててでも絞る」なので、ON は「できてない」として判定し％にも入れる。OFF は「できてる」、読めない時は「確認中」（行は消さない）。通常側の案内行は廃止した。
- **データセーバー（新規）**: ConnectivityManager.getRestrictBackgroundStatus() で読む。この読み取りはプラットフォームのアノテーション上も権限不要（ACCESS_NETWORK_STATE が要る同クラスの読み取りには @RequiresPermission が付いており、本メソッドには付いていないことを SDK の annotations で確認済み）。それでも読み取りに失敗した端末では項目自体を出さない。状態の意味: ENABLED（セーバーON・このアプリは制限対象）と WHITELISTED（セーバーON・このアプリだけ免除）はどちらも「端末のデータセーバーが効いている」ので「できてる（ON）」、DISABLED は「できてない（OFF）」。タップ → データ使用設定（モバイルデータと同じ画面）。

**モードの仕様**:
- 「限界まで節電」モードは ON/OFF の設定で、SharedPreferences（rules）のキー `limit_mode` に保持する。既定は OFF。
- スイッチはルール画面の設定スイッチ列に置く。v0.3.17 ではホームの通常チェックカードの最下部にも同じスイッチを置いて連動させていたが、v0.3.18 の情報整理でルールに一本化した（ホーム側は案内行に置き換え。§13）。
- **限界カードはモード OFF の時はホームに存在しない**（灰色表示や「OFFです」のプレースホルダは置かない。本人の指示どおり）。
- ％と円グラフはカードごとに独立: それぞれのリストだけで §12.5 の数え方（確認中は分母外）で計算する。限界カードの見分けは既存ロールの範囲で付ける: 見出し文字と円グラフのアークを warning ロールにし、面（読み物ガラス）・状態マーク・行の作法は通常カードと同一に保つ。読み上げは「限界まで節電 ○パーセント、（要約文）」。
- 権限: 追加なし（3つのまま）。判定は純粋関数 SavingChecklist のまま（evaluateNormal / evaluateLimit に分離し、各 Entry が属する段を持つ）。
- 未確認: 限界カードの出没の実感、warning 色の見出しの見え方、データセーバーの値が実機で実際に返るか、各設定画面への遷移は実機でしか判定できない（実機待ち行列）。

タップ先の追加分:
- Wi-Fi → Wi-Fi設定（ACTION_WIFI_SETTINGS、失敗時は無線設定へ）／モバイルデータ → データ使用設定（ACTION_DATA_USAGE_SETTINGS、失敗時は無線設定へ）／位置情報 → 位置情報設定（ACTION_LOCATION_SOURCE_SETTINGS）／NFC → NFC設定（ACTION_NFC_SETTINGS、失敗時は無線設定へ）／Bluetooth → Bluetooth設定（ACTION_BLUETOOTH_SETTINGS、失敗時は無線設定へ）／ダークテーマ → 画面設定／タッチ時のバイブ → サウンド設定（ACTION_SOUND_SETTINGS）。いずれも最終フォールバックは設定トップ。

## 14. ホームのスクロール無し化（v0.3.19、2026-11-20、本人指示「ホーム画面はスクロール無しでコンテンツが見れるようにしたい」→ v0.3.20 で仕組みを置き換え）

ホームの既定状態（チェックリストが両方とも畳まれ、「数値を見る」が閉じている状態）では**スクロールなしで全要素が見える**ことを仕様とする。

### 14.1 v0.3.19 が実機で溢れた原因（v0.3.20 で特定）
v0.3.19 は「レイアウト完了後に固定要素の実測高さを合計し、残りを顔に配る」（installHomeFit）方式だったが、本人の実機（Pixel 10 Pro、表示領域 約746dp）では最後の行（ダークテーマ）が下部ナビに半分隠れ、案内行と「数値を見る」チップが画面外だった。スクリーンショットの画素実測では顔スロットは **320dp（最大のまま）** で、正しく配分されていれば約212dpになるはずだった。原因は測定の循環である:

- EXACTLY な高さを持つ LinearLayout は、子を順に測る際、残りスペースで頭打ちされた AT_MOST スペックで後続の子を測る。顔が先頭で初期値 320dp を占めるため、その下のカードは残り幅に切り取られて測られ、チップは残り 0 で高さ 0 として測られる。
- つまり fit が合計したのは「必要な高さ」ではなく「既に入った分」であり、固定要素を約100dp 過小評価した。顔は最大のまま残り、入り切らなかった分が下から押し出された。
- 副次要因: 実機の行ピッチは約38.6dp（想定36dp）、要約が2行に折り返して頭は約60dp（想定52dp）。§14.4（旧）の解析予算自体も楽観的だったが、正しく実測できていれば顔が吸収できたはずの差であり、主因は測定方式にある。

教訓: 「実測」と称しても、測る対象がレイアウト制約で既に切り取られていると実測にならない。収める仕組みは測定ではなくレイアウト機構そのものに担わせる。

### 14.2 顔の可変サイズ（v0.3.20 の仕組み: ウェイト方式）
- 既定状態では、顔スロットは **layout weight 20** を持ち、上下に配置スペーサー（weight 3 : 4、レイアウト案A の比率）を伴う。LinearLayout が固定要素を自然な高さで測った残りを 3 : 20 : 4 で配るため、合計は常に表示領域と一致し、**測定に依存せず構造として溢れない**。余りの約74%が顔になり、残りはコンテンツ塊の上下の空気になる（上に固まってチップ下が死に余白になることはない）。
- フォントスケールや端末差で固定要素が想定より大きくても、減るのは顔とスペーサーだけであり、「収まる」性質は変わらない。これが v0.3.19 の教訓に対する安全マージンの取り方である（数値の余白ではなく、壊れようのない機構で担保する）。
- 顔の描画はスロットに追随する: 本体 rect の算出は BatteryFaceView.bodyRectDp に一本化され（ホームのガラスプレートも同じ関数から鏡像計算する）、本体の大きさ自体は FACE_H_MAX=320dp の設計寸法で頭打ちになり、スロット内での位置も同関数が決める。炎・キャップの頭上ゾーンと落影ゾーンはスロット高に比例して縮み、装飾寸法は sizeScale（スロット高／320）で比例縮小する。320dp の時は従来と完全同一の寸法になる。
- プレートの追随だけはレイアウト後のリスナー（installPlateFit）が担うが、これは高さを一切触らず、スロットの実寸をプレートへ鏡像するだけである。万一機能しなくても表示が少しずれるだけで、溢れにはつながらない。
- 状態ラベル・理由文・緊急ボタンの寸法と優先度は変えない。

### 14.3 チェックリストの開閉（v0.3.20、本人指示「パーセンテージの部分だけ見せ、詳細なチェックリスト部分はタッチした時に展開するようにしよう」）
- 既定状態で見せるのは**頭だけ**: ドーナツ＋％＋見出し＋要約（○つ中○つ）。項目の行リストは畳まれている。
- **頭全体が開閉スイッチ**: タップでそのカードの行が展開し、もう一度タップで畳む。頭の右端にシェブロン（⌄）を置き、開いている間は180°回転させる。頭には ripple を付け、読み上げには判定（％と要約）＋状態（開いています／閉じています）＋動作（タップで開く／閉じる）を含め、対応端末では stateDescription（展開中／折りたたみ中）も付ける。ドーナツ単独の読み上げは頭に一本化した（二重に読まない）。
- 通常カードと限界カードは**それぞれ独立に開閉**する。v0.3.19 の「限界モード時は片方だけ開く頭タップ切替」は、この仕様に置き換えて廃止した。
- 展開状態は Activity の生存範囲で保持する（タブを行き来しても保たれる）。アプリ再起動では既定＝両方とも畳んだ状態に戻る（永続化しない）。
- 案内行「限界まで節電はルールで切り替え ›」は通常カードの最下部に常時置く（行リストの外なので、畳んでいても届く）。限界モード ON の時は出さない（限界カードそのものが画面にあり、同じ意味を2回言わない。情報最小化 原則2）。
- 項目・判定・％計算・各行のタップ先は従来どおり変更なし。

### 14.4 チェックリストの密度トークン（v0.3.19 から不変）

## 16. 残量通知と充電tips（v0.3.22、2026-11-22、本人指示「好きな残りバッテリー時に通知を出せるようにしたい。また、充電に関してのtipsを見れる画面を表示して。スマホからスマホへの給電方法など、意外と知らない方法も載せて」）

### 16.1 残量通知（好きな残量で通知）
- 置き場所: ルール画面の「通知」グループ内、80%／発熱のスイッチの下。**マスタースイッチは置かず、選択そのものを設定とする**（何も選ばなければ通知は出ない）。
- 選び方: プリセット **50／40／30／20／10%** を M3 Filter Chip（複数選択）で提示。加えて「＋ 自分で決める」チップからスライダー（5〜95%、5%刻み）のダイアログで任意の値を追加でき、追加した値は Input Chip（×で削除）として並ぶ。プリセット値をダイアログで選んだ場合はそのプリセットの選択になる（保存形式は区別しない）。
- 保存: SharedPreferences（rules）の `level_alert_values`（文字列集合）。発火済み状態は `level_alert_fired`（文字列集合）に分けて持つ。
- 発火: 既存の定期チェック（約15分間隔）が担う。状態機械は純粋関数 **LevelAlerts.evaluate**（しきい値集合・発火済み集合・現在残量・充電中か → 通知すべき値と次回の発火済み集合）:
  - **放電中のみ**発火する。充電中は発火せず、発火済みにも入れない（抜いた時点で残量が下回っていれば次回チェックで通知される）。
  - 残量がしきい値**以下**になったら1回だけ通知し、発火済みに入れる。以後その値を下回り続けても繰り返さない。
  - **再武装**: 残量がしきい値より上に戻ったら（＝充電で回復したら）発火済みから外れ、次の放電で再び通知できる。
  - 選択から外したしきい値は発火済みからも落ちる。残量が読めない値（範囲外）は発火も状態変更もしない。
  - 大きく下がった場合は跨いだ全しきい値を高い順に通知する（通知IDはしきい値ごとに分け、上書きしない）。
- 通知: 既存チャンネル（電池の気づき）を流用し、既存トーンで「残量が ○% になりました／いまの残量は ○% です」。80%・発熱の通知は変更なし。権限追加なし。（v0.3.24: 現在値がしきい値と同値の時は本文を出さない — タイトルの言い直しになるため。§18。）
- **正直な注記**: 設定の直下に「チェックは約15分ごとのため、通知は残量に届いてから少し遅れることがあります」と常設する（定期チェック間隔の都合で最大で十数分遅れうることの明示。自動節電の間隔注記と同じ扱い）。
- テスト: LevelAlertsTest を新規追加（発火・再発火防止・充電中・再武装・選択解除・不正値など）。

## 19. 燃える→冷める：チェックリスト連動の状態表現（v0.3.27、2026-11-22、本人提案・モックアップ v4 承認）

本人の提案: 「節電できてないときは燃えている。チェックリストを埋めるほどバッテリーを冷ますオブジェクトが画面に増えていき、バッテリーが冷めていく（クーラー・扇風機・かき氷など）。チェックリストをこなすほど画面は涼しくにぎやかになる」。生成モックアップを4版作り、本人が v4（幾何学ベクター・淡色・点目・熱い側は真っ赤）を承認して実装した。表現の仕様と色値の正本は docs/ART_DIRECTION.md の「燃える→冷める（v0.3.27）」の節。

### 19.1 仕組み
- **熱さ** = 通常チェックリスト（7項目）の判定可能項目に対する NG の割合。判定は純粋関数 `HeatScene` に分離し、単体テスト（HeatSceneTest）で担保する。UNKNOWN・INFO は分母外（SavingChecklist.percent と同じ正直な数え方）。判定できる項目が無い時は熱さ無し = 従来（v0.3.23〜）の顔のまま。
- **炎**: 熱さの段階（0／〜0.34／〜0.67／超）で 0／3／5／7 個、大きさも段階連動。本体の周囲の固定アンカーに幾何学的なしずく型で描く。揺れは既存のアニメーション時計に相乗りする穏やかな揺れだけ。
- **液体**: 色が熱さで 淡青→淡ピーチ→濃い赤 と補間される（キャラ表現専用の色、テーマの状態色とは別）。気泡は熱いほど多く・速い。殻のティントも熱さでブレンドする。
- **口**: 熱さ 0 = 笑いの弧、0.6 以上 = ギザギザの震え口、それ以外 = 真一文字。充電中は常時笑いの弧（炎なし、稲妻は従来どおり）。
- **冷ます物**: 通常7項目の OK に対応する物が本体の周囲に1つずつ増える（対応表は ART_DIRECTION が正本）。置き場はキャラの周囲だけに固定し、案Eのミニマル白は壊さない。限界モード側の6項目は対象外。
- **バッテリーの形**: 本体上部に金属のリムバンド（本体高 7.5%）を追加し、端子キャップと合わせて「バッテリーと分かる形」にした。

### 19.2 正直さの担保
- 温度チェックが NG（実測の発熱）の時は、他の項目が全部埋まっていても炎を段階1以上残す — 「冷めている」絵で実測を覆わない。
- 熱さはチェックリストの判定そのものから出す。ホームの顔とチェックリストカードは同じ `evaluateNormal` の結果を共有する（MainActivity）ので、絵と一覧が食い違うことはない。
- ウィジェットも同じ読み取り（ChecklistReader を共有化し、WidgetUpdater も同じ経路で判定する）。

### 19.3 実装メモ
- `HeatScene.kt`（新規）: 熱さ・炎段階・口・物の集合・粒子活性・液体色の補間を決める純粋関数。Android クラスに依存しない（色補間は整数演算）。
- `ChecklistReader.kt`（新規）: MainActivity のチェックリスト読み取りを Context ベースに切り出し、ホームとウィジェットで共有する。
- `BatteryFaceView`: バンド・炎・物の描画、熱さ連動の液体色と気泡、熱さ連動の口。アニメーションループは既存のものに相乗りし、動きを減らす設定では静止画になる（従来どおり）。
- `WidgetFaceRenderer` / `WidgetUpdater`: 静止画にも同じ形・熱さ色・炎・物を反映（炎は直立、扇風機の羽根は静止）。
- 権限は不変（3つ）。バージョンは 0.3.27 / code 30。

### 19.4 検証と未確認
- テスト: 既存119件＋HeatSceneTest 13件 = 132件（JUnit 直接実行で全合格を確認すること — ビルド記録に残す）。
- 未確認: 実機での見え方（炎・物の大きさ感、バンドの読みやすさ）、動きの感じ方（炎の揺れ・扇風機の回転が「うるさくない」か）、小さい顔（スロット縮小時）に物が窮屈にならないか、ウィジェットの静止画の見栄え。いずれも実機待ち行列で扱う。
