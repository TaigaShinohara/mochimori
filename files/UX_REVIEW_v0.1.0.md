# もち守り v0.1.0 UX審査記録（2026-11-18）

審査: パソパソ監査（meaningful_app_design / minimal_information_design / concept-driven-ux / mobile_onboarding）＋ 独立審査（作成者の結論を渡さない分離入力）。両者はほぼ一致。

## 判定: 条件付き合格
有効範囲: 「ホーム中央の2つの顔で状態が伝わるか」の体験検証のみ。ストア訴求・MVP移行は必須指摘の解消が前提。

## 一致した核心
良い点: 顔の主役は成立（260dp中央、炎アニメ／結晶の形の区別）、判定は説明可能な純粋関数、権限はWRITE_SETTINGSのみで正直、気づき最大3件・サンプル明記。

必須指摘（独立審査 R1〜R6、パソパソ監査と一致）:
- R1 自動プロファイルは未実装なのに「作動中」と表示 — コンセプト「何もしなくても」と正直さへの違反
- R2 通知トグル2つがダミー（保存だけで通知コードなし）
- R3 ルール階段が起きない出来事を説明。緊急時（15%以下）は逆に「やることなし」が出て省電力1タップが出ない
- R4 「今週の無駄」は今週のデータでない（瞬間値＋サンプル）。良い状態の項目も無駄件数に混入
- R5 気づきに「直す」導線なし。ホームの修正も理由と無関係に明るさ一律下げ（コメントは消灯も下げると書くが未実装）
- R6 オンボーディングと権限の事前説明が存在しない

推奨（R7〜R10＋パソパソ追加）:
- R7 ホーム文字量が上限超過（実測行・推定・注記の3行追加、残量の三重表示、-1/255等の不明値表示）
- R8 「あと何時間」は固定係数×18h。注記はあるが太字の断定形と強弱が逆
- R9 顔に読み上げ情報なし、動きを減らす設定への配慮なし、Switchラベル未紐付け
- R10 充電中が判定に含まれない（設計の「充電中は解除」に反する）
- 追加A: アート方針が文書化されていない（プロジェクトに ART_DIRECTION なし）。実装は白背景＋既定ボタンで、設計の「深いネイビー＋青白／Simple Glass」と未接続
- 追加B: タブは既定Buttonで選択状態が文字色のみ — 状態表現が弱い

未確認: 実機での見え方、TalkBack、コントラスト、初見3秒テスト、ダーク環境（現行はLightテーマ固定）。

## v0.3 設計への反映（DESIGN.md 改訂済み）
1. 正直さの原則を強化: 画面の文言は「実際に起きること」だけを書く。実装が追いつくまで約束を小さくする。
2. v0.2.0 の実装範囲: ①緊急時（15%以下）は省電力1タップをホームに実際に出す ②充電中は専用の顔・文言に切替 ③通知（80%／発熱）を実実装しトグルを本物にする ④自動プロファイルは WorkManager 定期チェック（15分間隔）で実際に明るさ・消灯を切り替える（遅延ありを正直に注記） ⑤気づきは当面「今の無駄」に改称し項目ごとに理由対応の直すボタンを付ける。週集計は履歴保存を入れてから「今週」に戻す ⑥初回3画面オンボーディング（自動／1タップ／できない＋権限用途） ⑦ホームは顔＋ラベル＋理由1行＋アクションだけに削り、実測値は長押し/詳細へ、推定は小さく ⑧顔に読み上げ説明、動きを減らす設定で静止画、Switchラベル紐付け ⑨アート方針を文書化してから画面に適用（深いネイビー＋青白、Simple Glass読み物ガラス）。
