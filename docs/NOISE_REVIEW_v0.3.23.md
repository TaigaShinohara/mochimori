## 4. 対照表（見比べ）

**場面：** ホームを開いて今の状態を見る／充電する／初回起動／コツを読む／通知を受け取る
**全項目数：** 66　**ノイズ率（整理前）：** 9 ÷ 66 ≒ 13.6%

| 必須＋支援（57件） | ノイズ（9件） |
| --- | --- |
| 顔 — 見るだけで状態が分かる（必須） | オンボーディング見出し「もち守り」 — ツールバーと同画面の重複 |
| 残量の常時行 — 残量表示の正本（必須） | 理由文の「・N%」×2・「（N%）」— 常時行の言い直し |
| 状態ラベル＋理由文 — 判定と理由（必須） | 「抜くのがおすすめです」— 理由文の助言の言い直し |
| 階段カード — 自動で起きること（必須） | 残量通知の同値時の本文 — タイトルの言い直し |
| 遅れ注記 — 正直さの担保（必須） | コツ導入文 — タイトルと見出しの言い直し |
| チェックリスト・通知・コツ本文ほか支援49件 — 各必須への助け先あり | 残り時間行の「（目安）」— 「約」との二重表記 |
| 数値行（残量以外） — 生値の一覧（支援） | 数値行の「残量」部分 — 常時行の言い直し |

見比べの確認： ノイズはすべて文言レイヤーの「言い直し・重複」で、機能・情報の
必須項目はノイズ側に1件も混ざっていない。支援が必須より目立つ配置は無い
（チェックリスト頭が常時表示なのは本人の要望による常設で、主役は顔のまま）。

### 理由文の整理後の形（T6–T8 の実行結果）

- 充電中 80%未満： 「充電中・N%まで充電しています」→「充電中です。80%で抜くと長持ちします」
  （％の重複を消し、代わりにアプリ既定の目安＝80%で抜く、という差分情報を1つ足した。
  文字数は +2 字だが、同じ数値の二重表示が消え判断材料が増えるため、スキルの
  情報量テストの「理由を記録すれば許される変更」に当たる。理由はこの記録が担う）
- 充電中 80%以上： 「充電中・N%です。抜くと長持ちします」→「充電中です。抜くと長持ちします」
- 緊急： 「残量がわずかです（N%）」→「残量がわずかです」

## 5. 要判断として残したもの（実行せず）

- **コツ画面の畳み方**： 8件の長文は支援だが、1画面に全展開している。グループ単位の
  折りたたみ化は画面構成の変更になるため、今回は導入文の削除に留めた。畳むかどう
  かは本人の判断で決める。
- **ツールバーのアプリ名**： 全画面で「もち守り」を出し続けるのは構造表示だが、
  M3 の標準シェルであり現在地の文脈でもある。シェル変更に近いため今回は維持した。
- **チェックリストの項目数（通常7＋限界6）**： 全項目に判定文が付く（判定の裏付け）
  ため削減対象ではない。項目自体の廃止は本人の要望で増やした経緯のある機能判断
  なので、本監査では扱わない。

## 6. 重複の排除結果（例外を含む）

正本に寄せた情報：
- **残量** → 正本はホーム常時行（I2）。折りたたみ数値行と理由文3か所から消した。
- **「抜く」助言** → 正本は理由文。ホームの追加行（T11）を消した。
- **アプリ名** → 正本はツールバー（とランチャー名）。オンボーディング見出しを消した。
- **残量通知の現在値** → タイトルが正本。同値の時は本文を出さず、異なる時だけ差分として出す。

例外として残した再表示（理由つき）：
- **チェック行の値（明るさ・温度）と数値行の併存**： §13 の役割分担の既存決定
  （チェック行は判定の根拠、数値行は生値の一覧）。主役が違うため残す。ただし
  残量だけは常時行が A ランクの正本なので数値行から外した。
- **ドーナツ％と要約文の個数**： 図形と数字の併記だが、要約は「何つ中何つ」という
  ％に変換できない正確な個数を担うため残す。
- **ホームHEAT行と冷却ダイアログの「ケースを外して涼しい場所で休ませる」**：
  ホーム側はボタンが置けない状態の唯一の内容（正直さ＋その場の対処）、ダイアログは
  詳細手順の正本。要約と詳細の関係として残す。
- **約15分トースト（1回だけ）と遅れ注記（常設）**： 対象が違う（自動節電の間隔／
  残量通知の遅れ）うえ、片方は一回限りで時点が重ならないため残す。
- **オンボーディングの説明とルール画面（階段・許可行）**： 初回説明と、時間が空いた
  再訪で見返しに来る場所の正本。スキルの再表示例外（再訪・見返しの場所）に当たる。
- **コツの「熱」tipsと冷却ダイアログ**： 読み返しに来る場所での再掲は例外として残す。
- **顔・頭の読み上げ名（contentDescription）**： 非視覚的な情報は重複に数えない
  （スキルの明記どおり）。

## 7. A／B／C の仕分け（残った項目）

- 必須×A： 顔、残量常時行、状態ラベル、理由文、下部ナビ、階段カード、自動節電スイッチ
- 必須×B： 残量チップ群（選ぶ時だけ確実に届く）、許可フロー（必要な時だけ）
- 支援×A： チェックリストの頭（ドーナツ＋要約）のみ。理由： 本人の要望でホーム常設の
  判定要約であり、顔（必須）の裏付けとして置く。行そのものは B（畳み）
- 支援×B： チェック行、折りたたみ内の全行、コツ本文、ダイアログ、通知（届く時だけ）
- 支援×C： なし（別場所へ移したものは今回はない。到達は §8 で確認）

## 8. 検証（静的確認と仮判定）

- **重複テスト（実施）**： 出現箇所リストで再確認した。残量の出現はホーム常時行・
  チェック行の根拠値（温度・明るさと同格の扱いは例外として記録）・ウィジェット
  （別表面）だけになり、同じ画面で同じ数値が2か所に立つ重複は解消した。
- **コンセプト照合（実施）**： 残った57件すべてに判定文か助け先が付いている（§3）。
- **到達確認（実施）**： 消した情報の再到達 — 残量＝常時行（0タップ）、抜く助言＝
  理由文（0タップ）、アプリ名＝ツールバー（常時）、コツ導入文＝固有情報なし
  （グループ見出しが代替）。代表タスク「残量が減った時に鳴らす値を変える」は
  ルール → 通知グループ → チップ、の従来経路のままで完遂できる（変更なし）。
- **折りたたみテスト（実施）**： 見出し・トグルの文言は変更していないため従来どおり
  （「数値を見る」で中身が推測できる）。
- **アクセシビリティ静的確認（実施）**： 読み上げ名・色・タッチターゲットは不変。
  消したのは可視テキストの重複だけで、非視覚の情報は消していない。
- **ぼかし見（仮判定）**： 主役（顔）は不変で、ホームの塊の数は変わらない。
- **未確認（人間の初見でしか判定できない）**： 3秒テスト、無読テスト、親指テストは
  未実施。実画面が得られたら最初に確かめる項目は「充電中のホームで、理由文が
  ラベルと並んでも二重に読めないか」。
