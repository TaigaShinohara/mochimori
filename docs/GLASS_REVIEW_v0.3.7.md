# もち守り Simple Glass 監査・適用記録（対象 v0.3.7 → 適用版 v0.3.8）

実施: 2026-11-19。本人の決定「シンプルガラスを採用するのでシンプルガラススキルで全体を見直して」を受け、Simple Glass スキル（SKILL.md＋references/parts.md＋references/quality.md）を正本として全画面を監査し、適用した。色の役割（ひんやり淡青／注意オレンジ／緊急ピンク／構造・紫）と「色だけに頼らない形の区別」は ART_DIRECTION の従来方針どおり不変で、変えたのは質感だけである。続くデザイン整備の記録は docs/DESIGN_REVIEW_v0.3.7.md。

**プラットフォームの前提（正直な線引き）**: 本アプリは Kotlin の View ベース（Material Components 1.12.0）、minSdk 26。

- 背景ぼかし（backdrop blur）は、画面内 View に対してはプラットフォームに手段がない。RenderEffect は「その View 自身の描画」をぼかすもので背後はぼかせない。ウィンドウ単位の blur-behind はダイアログ等の別ウィンドウ専用。本アプリにダイアログはない。→ **背景ぼかしは未適用**とし、スキルのフォールバック（web.md の考え方: 読み物ガラス以上は背景色だけでも分離する濃さを維持する）に沿って、**代替＝半透明グラデーション面＋スペキュラ縁＋土台の光が透ける**で近づけた。
- Compose への移行はしない（本作業の指示どおり）。

## 1. 適用したもの（箇所と数値）

### 1-1. 標準の土台（quality.md §1 の型）— 新規共通コンポーネント `AppBackgroundDrawable`

- 全画面共通の1つの背景を root に敷いた（画面ごとに作らない）。従来は `colorSurface` のベタ塗りだった。
- グラデーション3点: 紙色（colorSurface）→ 主役の淡色（colorPrimaryContainer）→ もう1色の淡色（colorTertiaryContainer）。斜め方向、隣り合う色は淡色同士で段差は小さい。
- 光（blob）3つ（テンプレどおり）: 左上に主役色の淡色（primaryContainer）、右下に副色の淡色（tertiaryContainer）、中央下に3色目（secondaryContainer）。直径 約340dp（正本の 280〜360dp 帯）、画面端から外へはみ出させ、放射グラデーションで透明へ落とす（View では放射グラデーションの減衰そのものがぼかしの代替。ぼかし量 60〜80dp 相当の柔らかさはグラデーション半径で近似）。
- 光の色はすべて淡色ティント（原色は置かない）。色はテーマロール経由で解決するので、土台に限っては Dynamic Color の影響も受ける（土台はシステム色でよい、という従来の線引きのまま）。
- 色は「面に塗らず光で透かす」: ガラス面の色気は、この土台の光が面を通して見えることで出す（§1-2）。

### 1-2. ガラス面（新規共通パーツ `GlassDrawable`）

面は正本の種別からだけ選んだ。全ガラス面に共通: やんわりグラデーション（上→下・同系色・段差は不透明度 約8pt）と、ふちハイライト 1dp（上＝白 75%／ダーク 38% → 下＝白 15%／ダーク 6% のグラデーション stroke）。

| 面 | 適用先 | 数値（ライト／ダーク） |
|---|---|---|
| 読み物ガラス | 気づきの項目カード（従来 colorSurfaceContainer のベタ） | 白 62%→54% ／ 白 19%→13%（正本 58%／16% のグラデ段どおり） |
| 淡色ティント面（ガラス化） | ルールの階段カード3枚（primary／warning／error の container） | container 色を 94%→88% で重ね、上端は白を混ぜた側から引く。役割色と on-container 文字のコントラストは従来とほぼ不変（§3） |
| 読み物ガラス（帯） | トップバー、下部ナビゲーション | 読み物ガラスと同じ数値、角丸0の帯＋ふちハイライト |
| ベタ（変更なし） | 主ボタン（Filled）、気づきカード内の直すボタン、スイッチ ON、プログレスの進み | 役割色ベタのまま（正本どおり主アクションはガラス化しない） |

- カードの角丸は Medium 12dp → **Large 20dp**（Simple Glass のカード帯 20〜28dp の下限。M3 シェイプトークンの Large と一致させた）。
- 実装方式: MaterialCardView の自前 fill は透明にし、ガラスは内容の背面に敷く全寸の子 View が描く（MaterialCardView の形状・outline の挙動を壊さないため）。影は従来どおり付けない（面は透けと縁で分離）。

### 1-3. 状態の完全性（quality.md §3）

- 操作パーツの状態は M3 コンポーネント標準に委譲する従来方針のまま: ボタン（押下・無効）、スイッチ（ON=役割色ベタ／OFF=トラック、色＋つまみ位置の両方で表示）、ナビゲーション（選択中はインジケータピル＋ラベル、色だけに頼らない）、プログレス（軌道=読み物ガラス寄りの surfaceVariant／進み=役割色ベタ）。parts.md の各パーツ行と矛盾しないことを確認した。
- 入力欄・ダイアログ・シート・メニュー・トースト面は本アプリに存在しない（トーストは OS 標準）ため、重ね面（86%／32%）の適用先はない。

## 2. 代替・未適用にした項目（理由つき）

| 項目 | 扱い | 理由 |
|---|---|---|
| 背景ぼかし（blur 24px／saturate 185% 相当） | **未適用**、代替は §1 のとおり | 画面内 View に backdrop blur の手段がない（前提参照）。面の濃さは「ぼかしなしでも分離する」側に倒し、読み物ガラスの正本数値（58%／16% のグラデ段）をそのまま使った |
| 下部ナビの浮遊型（角丸 24〜全丸） | **未適用**（帯型のままガラス化） | 浮遊化は edge-to-edge のインセット処理と一体で、実機確認なしに形を変えるとレイアウトを壊すリスクが高い。帯型でも読み物ガラス＋ふちハイライトは適用済み |
| 役割色ベタのグラデーション（白+8%→黒−4%） | **未適用** | 主ボタンは MaterialButton の MaterialShapeDrawable が状態（押下・無効・リップル）を担っており、背景を差し替えると状態表現を壊す。正本の主原則「主ボタンはベタ維持」は満たす |
| 補助文字色の正本 hex（#554D44／#D8CFC2） | **未適用**（現行 onSurfaceVariant を維持） | 正本の hex は暖色系ニュートラル前提。本アプリの世界は青白系（アート方針）で、暖色の補助文字は世界の色と競合する。コントラストは現行色で 4.5:1 を満たす（§3）。色の役割は質感変更のついでに変えない、という正本の禁止事項にも沿う |
| オンボーディングの進み具合ドット | 概ね合致として記録 | 現行は図形（●／○）で形の区別はある。色の付与はデザイン整備（作業2）で tertiary のベタ色を付けた（DESIGN_REVIEW_v0.3.7 参照）。横長ドット化は新規パーツになるため見送り |
| 顔（BatteryFaceView）のガラス | 監査のみ、描画は不変 | 顔は ART_DIRECTION の顔の描画仕様が正本のカスタム描画で、ガラス面グラデーション＋上辺スペキュラ＋左端の光の帯を既に持ち、Simple Glass の核（半透明の面＋ふちの光）と同型。数値の当て直しは顔の状態判別（液体・炎・結晶）を弱めるリスクがあるため行わない。今回の顔の変更は液体の動きだけ（作業3） |

## 3. コントラストの静的計算（ゲート1の根拠）

色値からの静的計算（実測ではない）。読み物ガラスは一番薄い下端（ライト白54%／ダーク白13%）× 一番強い光の位置（blob の中心色）という最悪条件で測った。

| 組み合わせ | ライト | ダーク | 基準 |
|---|---|---|---|
| 本文 onSurface × 読み物ガラス | 14.71:1 | 7.22:1 | 4.5:1 ✓ |
| 補助 onSurfaceVariant × 読み物ガラス | 7.15:1 | 5.04:1 | 4.5:1 ✓ |
| 階段カード on-container × ティント面（88%側） | 8.08〜12.6:1 | 8.08〜10.63:1 | 4.5:1 ✓ |
| 状態ラベル（大文字・Headline）× 土台 | 3.62〜5.87:1 | 7.93〜9.40:1 | 3:1 ✓ |
| 見出し tertiary × 土台 | 8.96:1 | 7.84:1 | 4.5:1 ✓ |

観察事項（今回未変更）: 主ボタンの白文字 × warning #E65100 は 3.79:1。LabelLarge（大きな文字扱い）の 3:1 基準は満たすが 4.5:1 には届かない。これは v0.3.8 以前からの M3 テーマトークンのペアリングで、ガラス面ではない（ベタ面）。直すには固定の状態色か on 色の変更＝アート方針の色そのものの判断が要るため、質感適用の範囲では触らず観察事項として残す。

## 4. クオリティゲート12項目の判定（quality.md §4）

コード照合＋§3 の静的計算に基づく判定。実画面でしか判定できない部分は「仮判定」とし、未確認は §5 に残す。

| # | 項目 | 判定 | 根拠・対処 |
|---|---|---|---|
| 1 | コントラスト 4.5:1（大文字 3:1） | 合格（静的計算） | §3。最悪条件（最薄の下端×最強の光）で全て基準以上 |
| 2 | 土台は標準テンプレ、光は4つ以内 | 合格 | §1-1。グラデーション3点＋光3つ、共通コンポーネント1つに集約 |
| 3 | 面は5種から選択、全面にやんわりグラデーション | 合格（一部未適用を明記） | ガラス面は全て GlassDrawable のグラデーション＋縁で統一。役割色ベタのグラデーションだけ未適用（§2、理由はコンポーネントの状態表現の保護） |
| 4 | ガラスの階層（入れ子なし） | 合格 | 背景→ガラス1層のみ。カード内にガラスを重ねていない。スイッチ行・本文は面なし |
| 5 | 主アクションはベタ、主役級ボタンは1つ | 合格 | 従来どおり。画面の主アクションは Filled（役割色ベタ）1つだけ |
| 6 | 余白はスケール内、セクション間が詰まっていない | 合格（今回是正） | 残っていたスケール外の値 3件を是正: ラベルの上下パディング 3dp→4dp、気づきカード内バーの上下マージン 6dp→8dp、スイッチ行の上下パディング 10dp→12dp。他は従来トークン（20／12／16・12／24）がスケール内 |
| 7 | 文字サイズ4種以内、本文14以上・行間1.6、補助色 | 合格（補助色の hex のみ未適用） | M3 タイプスケールの従来運用のまま（Headline／Title／Body／BodySmall）。補助色は §2 の理由で現行色を維持し、コントラストで担保 |
| 8 | 色配分（地7・ティント2・ベタ1）、主役色1つ | 合格（仮判定） | 土台＋ガラスが地、階段カードと blob がティント、ベタは主ボタン・進み・選択中だけ。画面の主役色は状態色1つ（顔） |
| 9 | 角丸はトークン内 | 合格 | カード 20dp（Large トークン＝Simple Glass のカード帯の下限）、ピルはボタンとナビのインジケータだけ（従来方針） |
| 10 | 状態（押下・選択・無効・フォーカス）が定義 | 合格 | §1-3。M3 コンポーネント標準に委譲し、色だけに頼らない表示（スイッチ位置、ナビのピル＋ラベル）も従来どおり |
| 11 | ダークでも同じ点検を通る | 合格（静的計算） | ダーク側は独立した数値（白 19%→13%、ふち 38%→6%）を用意し、§3 の計算もダークで実施。ライトの流用はしていない |
| 12 | 小さい文字はベタ面＋濃い文字 | 合格 | チップ・バッジ類は本アプリにない。目安・注記（BodySmall）はガラス面ではなく土台の上に不透明文字で置かれ、コントラストは §3 の補助行で担保。進み具合ドットは図形であり文字ではない |

## 5. 未確認（実機でしか判定できない範囲）

- ガラスの実際の見え方: 透け具合、blob の柔らかさ、ふちハイライトの効き方、帯（トップバー／ナビ）の浮き方は実機画面でしか判定できない。コード照合と静的計算までの仮判定である。
- Dynamic Color が効いた端末での土台の色味（土台はロール経由のため端末色に寄る）。
- ライト／ダーク両テーマの実画面、大きな文字サイズでの崩れ、TalkBack の読み上げ順。
- これらは実機待ち行列の扱いとし、本人が触った時の一言か、同条件の変更前後スクリーンショットが得られれば判定を確定できる。
