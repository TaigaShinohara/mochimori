# 情報整理の監査と再編（v0.3.17 → v0.3.18）

本人の言葉（2026-11-20）: 「ホームタブとルールタブについて、どこに何があるかちょっと分かりづらいかも。整理しよう」

物差しは meaningful_app_design（画面ごとの主役と3問テスト、統一感）と minimal_information_design（A/B/C ランク、重要度順＝上から下、同じ意味を2回言わない）。質感は Simple Glass のまま変えない。**機能・判定・項目は減らさない。再編は「移動とグルーピング」だけ**が今回の約束。

- ホームの主役: 顔（今の状態）。狙う気持ち: 「見守られてる。でも、うるさくない」。役割は「見る・直す」場所。
- ルールの主役: 自動プロファイルの階段。役割は「決める」場所。

## 2. 監査の指摘（分かりづらさの原因）

- **F-1 順序**: ホームで「数値を見る」（詳細＝B）がチェックリスト（直す対象＝A）より上にあり、「状態を見る → 直す」の流れが途中で詳細に逸れる。情報最小化の原則8（重要度順に上から）に反する。
- **F-2 混在**: 折りたたみの中身に「残り時間・健康状態」（これからと電池の状態）と「いまの数値」（現在の実測値）の2種類が見出しなしで混ざり、目当ての行を探すのに全行を読む必要がある。
- **F-3 設定の二重配置**: 限界モードのスイッチがホームとルールの2か所にある。「決める」操作が「見る」画面にもあり、置き場所の原則（ホーム=見る・直す／ルール=決める）とずれる。同じ意味を2回置く重複でもある。
- **F-4 値の二重表示の役割不明**: 明るさ等の値がチェックリスト行と数値行の両方に出るが、どちらが何のための数字か（判定の裏付けか、詳細値か）が文言・見た目で示されていない。
- **F-5 ルールの無見出し一列**: スイッチ5つが見出しなしで同格に並び、グループ（自動節電／通知／触覚／限界）が読み取れない。階段の主スイッチ「自動節電」が階段カードから離れている。
- **F-6 許可の不在**: 「決める場所」であるルールに、許可の状態確認と案内がない。許可が無いと自動節電が実際には動かない（チェックリスト側でも「確認中（許可が必要）」になる）のに、その入り口がルールにない。

## 3. 再編の計画（パソパソの指定どおり）

- ホームの順序を 顔 → 状態ラベルと理由 → 緊急時の直し方 → チェックリスト（通常／限界）→ 数値を見る（最後）に入れ替える。
- 折りたたみの中身を「残り時間と健康状態」と「いまの数値」の2グループに見出しを付けて分ける（項目自体は減らさない）。
- 限界モードのスイッチはルールに一本化する。ホーム側は削除し、代わりに通常カードの末尾へ案内行「限界まで節電はルールで切り替え」（タップでルールへ移動）を置く。
- チェックリストと数値の役割分担を、見出しと既存の状態マークで明示する（チェックリスト=判定が主役、数値=詳細値が主役）。
- ルールを見出しでグループ化する: 自動節電（階段＋主スイッチ）／通知／触覚／チェックリスト（限界モード）／許可（状態と案内を新設 — 既存の許可フローの入り口を「決める場所」にも置く導線の追加であり、新機能ではない）。

## 5. 削らなかった重複・残した提案

指定どおり、機能・判定・項目は1つも削っていない。残した重複と、今後の提案：

- **P-1（提案・見送り）**：階段カード×3に「今この段階です」の印を付けると、ルール画面を開いた瞬間に現在地が分かる。今回は見送り（段階の現在地表示はホームの顔と状態ラベルが担っており、二重の現在地表示になる恐れがあるため）。実機で迷うようなら次版で検討。
- **P-2（提案・見送り）**：許可グループに通知許可（POST_NOTIFICATIONS）の状態も並べる案。今回は WRITE_SETTINGS のみ実装した。通知許可の変更は OS の設定画面側の操作になるため、行を増やすと「押せるのにアプリ内では完結しない」体験になりやすい。必要になったら追加する。
- **P-3（判断）**：チェックリスト行の値と数値行の値の完全一本化はしない。チェックリストの判定には現在値の表示が必要（根拠を見せるため）なので、値を消すのではなく見出しとマークで役割を分けた。これは重複ではなく役割分担として残す。
