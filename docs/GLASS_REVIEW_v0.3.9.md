# GLASS_REVIEW v0.3.9 — UIアートの Simple Glass 統一（v0.3.10）

実施: 2026-11-20。本人の決定「UIアートはシンプルガラスにしよう。シンプルガラススキルで全体を見直しておいて」を受け、Simple Glass スキル（SKILL.md＋references/parts.md＋references/quality.md）を正本として全画面とバッテリーの顔を監査し、適用した。

前回（v0.3.8 適用／v0.3.9 是正）との違い: 質感の部分適用ではなく、**見た目の作風そのものを Simple Glass に統一する**一段進んだ適用。前回「監査のみ・不変」とした**顔の描画を今回は対象に含め、「ガラスの器」として作り替えた**。同時に、コントラストの再計算を最悪条件でやり直したところ、従来「合格」と記録されていた組み合わせに 4.5:1 を割るものが3件見つかり、スキルの正本の手段（面を厚くする／紙色のベールを挟す／色の使い方を正す）で是正した。v0.3.9 で回復した読みやすさは後退させていない（むしろ最悪条件の数値は全項目で改善または維持）。

色の役割（ひんやり淡青／注意オレンジ／緊急ピンク／構造・紫）と「色だけに頼らない形の区別」は ART_DIRECTION の従来方針どおり不変。Dynamic Color は使わない。固定パレット（深いネイビー＋柔らかい青白）も不変。

**プラットフォームの前提（不変）**: View ベース（minSdk 26）では画面内 View への背景ぼかし（backdrop blur）の手段がないため、ぼかしは未適用のまま、代替＝半透明グラデーション＋スペキュラ縁＋土台の光の透け、で近づけている（GLASS_REVIEW_v0.3.7 §前提）。

## 2. 直した内容

### 2-1. ダークの読み物ガラスに「紙色のベール」を挟んだ（ゲート1の是正）

- 再計算の結果: ダークで、土台の最も明るい光（primaryContainer #004B73）がカードの真裏にある最悪条件では、読み物ガラス（白 19%→13%）の上の**補助文字が約 3.8:1**（上端 19% 側）まで落ち、4.5:1 を割っていた。前回の記録（5.04:1）は Dynamic Color 時代の色前提の計算で、固定パレットでは成り立たなかった。白を増やすと背景が明るくなり逆効果のため、スキル正本の手段「紙色のベールを挟む」を採用。
- 実装: GlassDrawable のダーク読み物ガラスは、白グラデーションの下にテーマの surface 色（#0B1C26）を alpha 180（約71%）で敷く。最悪条件は上端で **4.69:1**、下端で **5.69:1**、本文は **6.73:1** に回復。ライトはベールなしで 7.15:1（補助）あるため変更なし。
- 見た目への影響: ダークのカードは「濃いネイビーの面に白の艶」となり、透け感はやや減るが、グラデーションとふちハイライトはそのまま残る。ゲートが薄さより優先する、というスキルの線引きどおり。

### 2-2. ライトの帯の下端を 88% → 94% に厚くした（ゲート1の是正）

- 再計算の結果: ライトで、帯の最も薄い下端（surface 88%）×土台の最も明るい光という最悪条件では、選択中タブの primary ラベルが **約 4.46:1** と僅かに割っていた（未選択は 7.4:1 で合格）。
- 実装: GlassDrawable.band のライトを alpha 235→224 から **245→240（96%→94%）** へ。選択中ラベルは最悪条件で **4.53:1**、通常位置ではそれ以上。ダークの帯（95%→90%、未選択 9.39:1／選択中 8.87:1）は変更なし。v0.3.9 の「帯は重ね面の厚さ」という判断そのものは維持。

### 2-3. テキストボタンの文字色を primary → secondary に（ゲート1の是正）

- 再計算の結果: ライトで「数値を見る」等のテキストボタン（primary #0277BD）が、ホーム下部の土台ティント（secondaryContainer 側＋中央の光）の上で **約 3.7:1** まで落ちていた（紙色の上では 4.58:1 で合格、ダークでは 4.9:1 以上で合格）。
- 実装: textButton の文字色を secondary（ライト #46617A／ダーク #A9C7DE）に変更。最悪条件で **5.02:1**（ライト）／**5.25:1**（ダーク）。secondary は「深いネイビーの補助」ロールで、ほぼ黒の本文（onSurface）との差（青み）で「押せる文字」として読めることも保った。色の役割の新設はしていない。

### 2-4. 主ボタンの横パディング 28dp → 24dp（ゲート6の是正）

- filledButton／primaryButton の左右パディング 28dp は余白スケール（4/8/12/16/24/32）外だった。24dp はスケール内であり M3 の既定値でもある。縦 10dp は M3 コンポーネント既定として記録のみ（スケールの対象は画面側の余白という従来の線引き）。

### 2-5. 顔を「ガラスの器」に作り替えた（本丸）

BatteryFaceView の描画仕様（縦型 1:1.55、液体パーティクル、炎・結晶・稲妻、状態色の役割）は一切変えず、質感だけを Simple Glass の言語に替えた:

1. **本体を半透明のティントガラスに**: Palette.glass を不透明ベタから、container 色の半透明グラデーション（alpha 240→230→220、同系色・上→下）に変更。階段カードのティント面（94%→88%）と同じ厚みの家族に揃えた。背後のオーラと土台の光が輪郭の縁（本体と cavity の間の 7dp の帯）を通して透け、「液体の入ったガラスの器」に読める。cavity（空洞部）は従来どおり不透明 — 残量の読み取りを守る。
2. **スペキュラのリムを新設**: 輪郭の内側 2.8dp に 1dp のリムを描き、グラデーションは GlassDrawable と**全く同じ数値**（上 白75%／ダーク38% → 下 白15%／ダーク6%）。カードや帯と同じ「ふちの光」の言語で顔がアプリ全体と揃った。従来の上辺の平らな白帯（alpha 42）はこのリムに役割を譲って撤去。
3. **反射の帯をグラデーションに**: 左端の光の帯は一様 alpha 15 の硬い帯だったものを、横方向に溶けるグラデーション（白 36 → 0）に替え、幅も少し広げた（0.16→0.20）。液体と喧嘩しない控えめさは v0.3.5 の判断を維持。
4. **器の内側に奥行き**: cavity の上に、内側上辺の影（黒 alpha 20 → 0）と底の明るさ（白 0 → 12）の深度グラデーションを重ねた。液体の下に描くので液面の読み取りには影響しない。
5. **輪郭の上端を明るく**: outline の上端ストップの白ブレンドを 0.30 → 0.45 に。ふちが上からの光を受けるガラスの縁らしくなる。中間ストップは状態色そのまま（純色）で、状態判別の強さは変えていない。

炎の基部は本体上辺の裏に隠れる描画のままだが、本体が半透明になったことで基部がごく僅かに透け、「ガラスの裏に炎が回り込んでいる」見え方に近づいた（意図せぬ副作用ではなく、器としての自然さとして記録する）。

## 5. 代替・未適用にした項目（理由つき）

前回までの記録（GLASS_REVIEW_v0.3.7 §2、GLASS_REVIEW_v0.3.8 §2）から継続するものは再掲せず、差分だけを記す。

| 項目 | 扱い | 理由 |
|---|---|---|
| 背景ぼかし（blur／saturate） | 未適用（継続） | 画面内 View に backdrop blur の手段がない。代替（半透明＋縁＋光の透け）も継続 |
| 下部ナビの浮遊型 | 未適用（継続） | edge-to-edge のインセット処理と一体で、実機確認なしの形状変更はリスクが高い |
| 役割色ベタのグラデーション（白+8%→黒−4%） | 未適用（継続） | MaterialButton の状態表現（押下・無効・リップル）を壊さないため |
| 補助文字色の正本 hex（#554D44／#D8CFC2） | 未適用（継続） | 暖色系ニュートラルは本アプリの青白の世界と競合する。現行色で §3 のとおり 4.5:1 を満たす |
| 顔の cavity の半透明化 | **未適用（今回の判断）** | 器の透け感は輪郭の縁とリムで出し、cavity は残量の読み取りを担う面として不透明を維持する。透けさせると背後のオーラの明暗で残量の境目が揺れる |
| 顔のキャップのガラス化 | 未適用（今回の判断） | キャップは金属端子であり、金属グラデーション＋中央ハイライト線が正本。ガラスではない部品までガラスにしない |
| 土台の光3つ目のテンプレ位置（中央下） | 逸脱を維持 | v0.3.9 の実機で「中央下の光が下部ナビのラベルを消す」ことを確認済み。テンプレより実機の読みやすさを優先する |

## 6. 未確認の範囲

- **ガラスの実際の見え方は実機でしか判定できない**: 顔の器の透け具合（縁の帯にオーラがどう透けるか）、スペキュラのリムの効き方、反射の帯の溶け方、cavity の奥行き感、ダークでベールを挟んだカードの質感（透け感が減りすぎていないか）は、コード照合と静的計算までの仮判定である。
- ライト／ダーク両テーマの実画面、Dynamic Color のない端末での見え方（全廃済みのため端末差はない想定だが実画面は未確認）、大きな文字サイズでの崩れ、TalkBack の読み上げ順も従来どおり未確認。
- これらは実機待ち行列の扱いとし、本人が触った時の一言か、同条件の変更前後スクリーンショットが得られれば判定を確定できる。
