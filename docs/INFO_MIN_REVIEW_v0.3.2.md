# もち守り 情報最小化 削減監査記録（対象 v0.3.2）

実施: 2026-11-19。本人の指示「情報を最小限にするスキルを使って全体を見直して」を受け、スキル minimal_information_design の作業の流れ（棚卸し → ランク付け → 仕分け → 置換検討 → 並び順 → 段階表示 → 検証）で**監査と記録のみ**を行った。**アプリのコードは変更していない（ビルドもしていない）。** 本書の削減案はすべて「提案」であり、適用は次版の実装作業で判断する。

物差し: **読まなくても分かるか。3秒で次にすることが分かるか。**

過去審査との関係: UX_REVIEW_v0.1.0（R7 ホーム文字量超過など）と DESIGN_REVIEW_v0.3.0（デザイン整備）で既に削り切った部分は、本書では「適合」として短く触れるに留め、新しい論点を優先した。

**判定の前提**: 実画面・初見の人は得られていない。数値比較・到達ステップ数・アクセシビリティ静的確認・ぼかし見はコード照合による**仮判定**であり、3秒テスト・無読テストは**未実施**（§7）。AI の見立てで合格にはしない。

## 1. 数え方（全画面で固定）

- **要素**: 利用者が「1つの意味のまとまり」として認識する単位。見出し1つ、カード1枚、行1行、ボタン1つ、顔1つを各1要素とする。畳まれた中身は数えない（開いた場合は別記）。
- **可視文字数**: 画面の初期状態（折りたたみは閉）で見える文字列の合計。改行・空白は除き、数字・記号（%・℃・〜・↓等）は1字として数える。状態で文言が変わる画面は代表状態で数え、バリエーションは注記する。
- **共通シェル**: ツールバー「もち守り」(3字)＋下部ナビ3ラベル（ホーム／気づき／ルール、計9字）＝12字・2要素は全画面共通のため、各画面の数値には含めず別枠で記す。
- **選択肢数**: 画面内のインタラクティブ要素（ボタン・スイッチ・トグル）の数。下部ナビ3件は共通分として別記。
- **色数**: 役割で数える。本文・背景の無彩色（surface 系）は1枠とする。
- 数値の目安（常時表示3割、主要1＋補助2、サイズ3〜4段など）は合格線ではなく「超えたら理由を記録する」トリガーとして扱う（スキル §数え方と数値の扱い）。

### 常時表示比率について（トリガーへの回答）

常時表示（A）の比率: メイン3画面の全23要素中 A は12要素＝約52%で、目安（3割）を超過する。理由を記録する: ①ホームは要素自体が6つしかなく、顔という主役1つで比率が構造的に上がる（密度が価値の画面ではないが、要素の絶対数が最小構成のため）。②ルールは設定画面であり、階段（主役）とスイッチ（操作対象）が画面の本体そのもの。③それでも C と判定した4要素（やることなし／気づきサブ文／固定値行／末尾注記）を消し、B の良好セクションを畳めば、常時表示は 12 → 実質9要素相当まで下がる。比率そのものより「C が残っていること」が問題であり、そちらを指摘の本体とする。

## 4. 指摘一覧（重要度・原則番号・削減案と行き先つき）

**必須 2件／推奨 10件。** 必須＝スキルの失敗条件に明記されたもの、またはアクセシビリティの必須確認項目に触れるもの。

### 必須

- **M-1（アクセシビリティ／検証節の必須確認）: ホーム HEAT 時の説明文のコントラストが目安未満の疑い。**
  説明文「アプリでは直せません。ケースを外し、涼しい場所で休ませると冷めます」は BodyMedium（通常サイズ本文）× warning 色 #E65100 を surface #F7FAFC 上に置く。静的な概算ではコントラスト比 約3.5:1 で、本文の目安 4.5:1 に届かない疑いがある（概算値であり確定ではない）。気づき見出しの warning は TitleLarge（大きな文字）なので 3:1 基準では概算クリア、cool #0277BD は概算 約4.5:1 で境界上。行き先: 実装時に実測し、HEAT 説明文は onSurface に寄せ、warning は見出し・バーの側にだけ残す案を第一候補とする。**実測するまで「不合格」とも「合格」とも言わない。**
- **M-2（原則4）: 折りたたみ「詳細を見る」の見出しが中身を推測できない。**
  スキルは「中身を見ないと見出しの意味が分からない折りたたみは失敗である」と明記する。現行の「詳細を見る」だけでは、中に残量・温度・明るさの数値があることが開く前に分からない。行き先: ラベルを中身が分かる短い文字へ（例「数値を見る」）。文字数はほぼ同じで判断だけが減る変更（原則1の情報量テストでも許容される型）。

### 推奨

- **R-1（原則5）: 気づきのサンプルカードの常設をやめる。** 見出し＋カードで約50字・画面の約36%。実データでないものが、実データの画面に常時居座っている。行き先: **消す**（行き先は「週集計の実装時に実データとして復帰」であり、情報自体の行き先は決まっている）。副次効果として、見出しとカード題で「サンプル」と2回言う重複も消える。なお R4 審査でサンプル明記が正直さの担保だった経緯があるため、消す判断は「実データが無い項目は画面に置かない」という原則5の判断であり、正直さの後退ではない（無いものは無い、が最も正直）。
- **R-2（原則1）: ルールの固定値行を消す。** 「節電に入る残量: 30%（固定）」は階段カード「節電 30%以下」の言い直し。行き先: **消す**（情報は階段に一本化）。
- **R-3（原則1・2）: ルールの末尾注記を消す。** 「設定はこの4つだけ。それ以外は既定値です」は数えれば分かるメタ説明。R-2 を消すと「4つ」の数も合わなくなる。行き先: **消す**。
- **R-4（原則1・2）: ホームの「やることなし」を消す。** 節電できてる時、状態ラベル・理由・この一文が三重に同じ意味を言う。顔＋ラベル＋理由で十分伝わる。行き先: **消す**。（充電中の「抜くのがおすすめです」は行動の指示であり意味が違うので対象外。）
- **R-5（原則2）: 気づきのサブ文を消す。** 「責めない。直せるものだけ出します」は利用者への情報ではなく作り手の姿勢表明。姿勢は文言全体のトーンで示すもの。行き先: **消す**。
- **R-6（原則1・4）: 気づきの良好セクションを畳む。** 「良い状態」見出し／題「明るさは控えめ」／詳細「…良い状態です」で同じ言葉が3回出るうえ、良い状態はホームの顔が既に担っている。行き先: 詳細の「良い状態です」を消し、セクション自体は**畳む**（既定では見出し＋件数だけ）。v0.3.1 で「0件時に良い状態の言葉を出す」是正をした経緯があるため、0件時の空画面対策の一文（「今は無駄なし。良い状態です」）は残す前提で、良好カードが出る場合の重複だけを対象とする。
- **R-7（原則4・5）: ホームの「目安 約X時間」を詳細折りたたみへ移す候補。** 残量%（詳細内）からの派生推定であり、顔とラベルが主役の画面では B が妥当。行き先: **畳む**（詳細内へ）。ただし DESIGN §4 は「イラストの下に『あと何時間』を小さく添える」を仕様としており、仕様変更を伴うため必須にはしない。移す場合は詳細側の到達は現行どおり1タップで変わらない。
- **R-8（原則5）: ルールの「約15分ごと」注記を後出しにする候補。** 正直さのために必要な情報だが、読むべきタイミングは「自動節電を初めて ON にした時」が中心。行き先: **後出し**（初回 ON 時／オンボーディング側へ寄せる）。常時表示をやめる場合も、情報の在り処（ルール画面内・到達1タップ以内）は維持すること。
- **R-9（原則1・3）: 文章を「数字だけ」「短い文」へ。** ①気づき無駄カードの詳細「いちばん大きい無駄です（現在 245/255）」— 「いちばん大きい無駄です」は件数が1件でも表示される順位の主張で、情報としての精度も低い。バー（図形）が量を既に示しているので、詳細は数値「245/255」だけにできる。②オンボーディング②の最長文「省電力モードは、ボタンから設定画面を開きます（自動では押せません）」(33字) は、括弧内の言い直しを削り「省電力モードはボタンから設定画面を開く」程度に短縮できる。行き先: どちらも**置き換える／短縮**（要素自体は残す）。
- **R-10（原則3・6・7）: 細部の語彙と動き。** ①オンボーディングに進み具合（3ドット等の図形）がなく、「あと何画面あるか」が分からない — 足す提案だが、判断回数を減らす図形であり、原則3の優先順位（図形）にも合うため、足す場合は同画面の何かを引く前提でなく単独で許容できる（記録する）。②フォント6段のうち BodyMedium の役割が3画面で曖昧 — サイズ自体は M3 準拠で正当だが、BodyMedium を使う箇所の役割（補助本文）を1つに寄せるのが望ましい。③顔の「きらめき（4点星の瞬き）」と充電バッジの脈動グローは、状態の意味そのものではない装飾アニメーションで、ART_DIRECTION「アニメーションは状態の意味そのものだけ（炎の揺れのみ）」と緊張関係にある（原則6「意味のない動きは入れない」）。v0.3.2 で本人の絵品質指示により入った要素なので削除提案ではなく、**観察事項**として記録する（静止画でも情報は完全に伝わるため、原則6の「動きは補助」の条件自体は満たしている）。

## 5. 置換の検討（原則3の優先順位で）

既に置換が効いているもの（適合）:

- **状態そのもの**: 顔（炎／結晶の形＋色＋残量の液面）が状態表示の本体であり、文字はラベル1語と理由1行だけ。原則3の最上位で伝えている。
- **図形と量**: 気づきの量はバー（LinearProgressIndicator）で示し、数値は詳細側の添えに留まる。ルールの階段は色の段階＋位置で状態遷移を示す。
- **色と状態の変化**: ナビの選択はインジケータピル＋ラベル、スイッチはハンドル位置＋色。色だけに頼っていない。

追加で置換できるもの: 指摘 R-9（文章→数字）、M-2（曖昧な文字→内容を示す短い文字）、R-10①（画面位置→ドットの図形）。
置換しないと判断したもの: 状態ラベル・理由1行は固有の意味（なぜ節電できていないか）を持つため短い文字が正解。スイッチのラベルは読み上げ名と兼ねており、アイコン化しない（見えるラベルを消しても読み上げ名は消さない原則にも適合済み: スイッチには contentDescription、顔には状態説明の contentDescription がある）。

## 6. 並び順とボタン位置（原則8）

## 7. 段階表示（原則6）

- 画面表示時の段階表示アニメーションは**現状なし**（画面は即時に差し替わる）。入れる価値の判定: ホームは要素6つ・気づきもカード最大5枚程度と少なく、段階表示で得られる利益が小さい。一方 ART_DIRECTION は「アニメーションは状態の意味そのものだけ」と定めており、表示演出の追加は方針と衝突する。**結論: 入れないのが正しい（理由をここに記録する）。**
- 状態の意味のアニメーション（炎の揺れ、液面の波）は適合。きらめき・充電グローの扱いは指摘 R-10③ の観察事項。
- 動きを減らす設定（ANIMATOR_DURATION_SCALE=0）では顔のアニメーションが止まり静止画になる実装済みで、静止画でも情報は完全に伝わる。適合。
